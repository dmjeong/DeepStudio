# 5.92 — 기본 분류 모델 Precision 계산 누락 수정

## 확인과 설계
ResNet·ConvNeXt의 `_classification_epoch`는 Accuracy, Recall, F1과 손실만
기록했다. 모든 검증 배치의 혼동행렬을 합친 뒤 클래스별 TP/(TP+FP)의 평균을
`precision_macro`로 함께 기록한다. 에폭마다 혼동행렬을 새로 생성한다.
계산·저장·화면 경로에서 다른 모델의 이전 값을 재사용하지 않는지 검사한다.

## 검증
서로 다른 합성 예측 두 묶음을 입력해 공통 분류 평가기의 결과와 비교한다.
각 묶음의 Best CSV와 저장 기록을 복원하여 Precision·Recall이 보존됨을 검사한다.
실제 Qt 위젯에도 두 완료 기록을 차례로 표시해 대시보드와 평가 표의 값이 바뀌는지 검사한다.
관련 Python 테스트 60개가 통과했다. 사용자 가중치로 학습한 검사는 아니다.

## 확인 범위
Precision 누락은 확인된 버그다. 사용자 환경에서 서로 다른 모델의 학습 완료 후
Precision·Recall이 같은 숫자로 나온 원인은 아직 확정하지 않았다.
동일한 혼동행렬이면 서로 다른 모델도 같은 지표가 나올 수 있고 표시 반올림도 있다.
누락 수정만으로 그 현상까지 해결됐다고 주장하지 않는다.

## 자동검사 보완
사용하지 않는 import를 제거했다. EfficientNet 검사는 이미 내려받은 파일을
명시적으로 전달하고, PatchCore 검사는 임시 설치 가중치 묶음과 manifest를 준비한다.
앱의 실행 중 자동 다운로드 금지 정책과 무결성 검사는 유지한다.
로컬에서 EfficientNet B0/B1의 공식 가중치 레이어 비교·학습 검사와 PatchCore
ResNet18/ResNet50/Wide-ResNet50-2의 학습·저장·오프라인 복원 검사가 통과했다.
CI 대상 Python 코드의 lint도 통과했다. Windows 실행 결과를 대신하는 것은 아니다.
