# 3.65 — PatchCore 보정·ONNX 배포 계약 수정

PatchCore는 정상 특징을 한 번 저장하는 방식이라 특징 뱅크 구축 자체는 빠르다. 이번 릴리스는
그 구축 완료를 자동 OK/NG 판정 준비 완료로 오인하지 않도록 보정 및 배포 경로를 분리했다.

- 정상과 불량이 모두 있는 `val` 또는 `test` split을 자동 보정 대상으로 우선 선택한다.
  두 클래스가 없으면 특징 뱅크는 저장하지만 UI는 `판정 미보정`으로 표시한다.
- 미보정 모델은 ONNX/C++ 배포를 거부한다. `None` 임계값을 0으로 바꿔 모든 결과를 NG로
  판정하던 경로를 제거했다.
- 새 체크포인트(schema 5)는 표준 최근접 패치 점수와 PatchCore 이미지 재가중을 기록한다.
  과거 체크포인트는 이전 점수 방식과 임계값을 그대로 유지한다.
- 과거 `full_range_v1` 체크포인트는 Python에서 계속 사용할 수 있다. C++ ONNX 배포는 Python과
  동일한 OpenCV 전처리를 기록한 새 체크포인트만 허용하므로, 기존 모델은 새로 구축·보정해야 한다.
- ONNX JSON은 학습 시의 중앙 크롭과 8비트/16비트 전체 범위 입력 계약을 기록한다. C++ 파일
  추론은 uint16 파일을 원래 범위로 읽어 처리한다.
- SAM2.1 Hiera 변형을 변경할 때 Qt가 index를 파일 경로로 해석해 예외를 내던 오류를 수정했다.

검증: 전체 Python·GUI·ONNX 회귀 테스트 864개 통과, 11개 건너뜀. PatchCore 학습·복원·점수·데이터
선택·ONNX·배포 번들·SAM2 모델 관리 경계조건을 포함한다. 이 개발 환경에는 CMake가 없어 C++
바이너리 빌드는 실행하지 못했다.
