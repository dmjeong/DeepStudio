# 9.33 — 작은 결함 분할 학습과 라벨링 이동 속도

새 학습 옵션(분할 손실 선택, 분할 클래스 가중치)이 들어간 간단한 기능 추가 릴리스이므로 사용자 버전 규칙에 따라 9.23에서 +0.1로 올렸다. 같은 릴리스의 버그 수정(라벨 정렬, 클래스 이름, 작업실 메모리)으로 버전을 따로 올리지 않는다. 이 문서는 로컬 Linux 개발 환경의 검증 기록이며 Windows 설치본의 실기기 승인 기록은 아니다.

## 구현

### 분할 손실 (`python/segmentation_loss.py`)

```
loss = CE(logits, target; weight=클래스 가중치, ignore=255)
     + (1 − mean_{c≥1} Dice_c)          ← "ce_dice"(기본)일 때만
Dice_c = (2·Σ p_c·y_c + 1) / (Σ p_c + Σ y_c + 1)   (255 픽셀은 p, y 모두 0)
```

- 결함 마스크는 대부분 배경이라 픽셀 CE의 평균은 결함을 놓쳐도 작다. Dice는 클래스별 겹침 비율이라 결함 면적과 무관하게 같은 크기의 신호를 준다.
- 클래스 가중치는 학습 크기로 줄인 마스크의 클래스별 픽셀 수로 계산한다(분류와 같은 `weights_from_counts`, 학습 픽셀 평균 1로 정규화). 학습 픽셀이 없는 클래스가 있으면 이름을 표시하고 학습을 시작하지 않는다.
- 학습 제외(255)만 있는 배치는 0 손실을 반환한다. 일반 CE는 0/0으로 NaN이 된다.
- 기본 모델(`train_builtin`)과 Custom CSP(`gui/core/trainer.py`)가 같은 클래스를 쓴다. 적용한 손실·가중치·픽셀 수는 `training.json`의 `training_config`와 실행 기록에 남는다.
- 설정: `TrainingConfig.segmentation_loss`(`ce_dice` 기본, `ce`는 9.23까지의 동작), `class_weights`. 데스크톱 학습 화면, 웹 API 검증, `train_builtin.py --segmentation_loss/--class_weights`에 연결했다.

### 학습 마스크 축소 (`python/dataset.py: resize_label_mask`)

```
원본 마스크 ──INTER_NEAREST_EXACT──▶ 출력 (픽셀 중심 정렬)
     │
     └─ 클래스별 coverage(출력 픽셀이 덮는 원본 면적 비율, INTER_AREA)
          └─ coverage>0 영역의 연결 성분(출력 해상도)마다
               · nearest가 남긴 픽셀 < 기대 면적 × 0.5        → 사라짐
               · 평균 coverage < 0.5(블록보다 얇음) & 2조각 이상 → 끊김
             이면 그 성분의 "배경" 출력 픽셀만 해당 클래스로 복원
```

- 다른 클래스와 255 픽셀은 바꾸지 않는다. 확대는 nearest 그대로다.
- 연결 성분을 출력 해상도에서 구해 4096²→512² 마스크 한 장이 약 50ms다(원본 해상도 연결 성분은 약 290ms). 데이터셋은 파일 경로·수정 시각·크기를 키로 축소 결과를 64MB까지 캐시한다.

### 라벨링 작업실 이동

- 닫은 작업창을 다음 창을 열기 전에 실제로 삭제한다. 중첩 `exec()` 안에서는 `deleteLater()`가 처리되지 않았고, Python 참조 순환이 원본 해상도 버퍼를 잡고 있었다.
- 64×48 썸네일을 창 사이에서 재사용하고, 닫힌 창의 남은 썸네일 작업을 멈춘다.
- 다음·이전 원본 이미지를 백그라운드에서 디코딩한다(최대 2장/256MiB).
- 진행 방향의 다음 마스크 문서를 백그라운드에서 읽고 렌더링한다(1장). 클래스 목록이나 이미지·정답 파일의 수정 시각·크기가 달라지면 버리고 새로 읽는다. 이미 객체 ID가 부여된 문서는 렌더 캐시를 유지한다.

### 데이터셋 화면: 이미지가 아닌 영역 단위 클래스

분할·탐지의 클래스는 이미지 전체가 아니라 이미지 안의 영역에 붙는다. 9.23까지는 분류처럼 "이미지가 어느 클래스인가"로 보여줬다.

| 위치 | 9.23 | 9.33 |
|---|---|---|
| 이미지 추가 줄 | `대상` + `클래스` 선택 (이미지를 클래스에 넣는 것처럼 보임) | `대상`만. 클래스는 정답 그리기에서 영역마다 지정 |
| 통계 표 | 그 클래스 픽셀이 있는 이미지 수. `background` 행은 사실상 전체 | `영역 수 · 이미지 수`, `배경만`, `미라벨` 행 |
| 썸네일 배지 | `background, scratch` | `scratch 3 · dent 1` / `배경만` / `미라벨` / `정답 오류` |
| 필터 | 전체 / background / scratch … | 전체 / scratch … / 미라벨 이미지 / 배경만 있는 이미지 |
| 클래스 삭제 | 상단 클래스 선택값 | 삭제할 클래스를 묻는 창 (배경 제외) |

- 영역: 마스크는 같은 클래스 픽셀의 8-연결 성분, 박스·폴리곤은 정답 한 줄이다. 배경(0)과 255는 영역이 아니다.
- `scan_dataset`이 이미지별 `regions`, 분할별 `regions`/`empty`/`unlabeled`를 추가로 돌려준다. 기존 `classes`는 그대로다. 웹 API는 `status=empty` 필터를 받는다.
- 마스크 영역 집계는 파일 경로·수정 시각·크기로 캐시한다. 2048² 마스크 60장의 첫 탐색 1.69초는 이전과 같고, 다시 탐색할 때 1.58초 → 0.01초다.

### 클래스 이름과 정렬

- 기본 분할 체크포인트와 배포 JSON이 `"0".."N-1"` 대신 프로젝트 클래스 이름을 저장한다. 클래스 순서가 다르면 이어학습을 거부하고, 추가 학습은 헤드를 새로 만든다.
- 학습 마스크(데이터셋, SAM2 손실 대상)를 픽셀 중심 nearest로 줄인다. `INTER_NEAREST`는 4배 축소에서 라벨을 이미지보다 평균 0.38 출력 px 오른쪽·아래로 밀었다. C++ 추론의 마스크 확대도 OpenCV 4.5 이상에서 `INTER_NEAREST_EXACT`를 쓴다.

## 검증 기록

환경: Linux x86_64 컨테이너, Python 3.11, PyTorch CPU, PySide6 offscreen, OpenCV 4.6(C++). GPU·Windows 결과가 아니다.

### 손실 비교 (`unet_resnet18`, 1채널, 입력 128², 20 epoch, seed 2개 평균)

합성 데이터: 256² 이미지 48/24장, 2~3px 흠집(클래스 1)과 반지름 2~5px 점(클래스 2). 검증셋 학습 해상도 기준.

| 손실 | 클래스 가중치 | 결함 mIoU | 결함 검출률 |
|---|---|---|---|
| CE | 없음 | 0.383 | 0.569 |
| CE | Sqrt | 0.674 | 0.891 |
| **CE + Dice (기본)** | 없음 | **0.688** | **0.902** |
| CE + Dice | Sqrt | 0.672 | 0.879 |

CE만 쓸 때 seed에 따라 0.47/0.29로 크게 흔들렸다. Dice를 더하면 가중치가 없어도 안정적이고, 두 보정을 겹쳐도 더 좋아지지 않았다. 그래서 기본값은 CE + Dice, 가중치는 선택 사항으로 둔다.

### 마스크 축소 (2048²→512², 무작위 위치·각도 200개씩)

| 결함 | nearest | 보정 |
|---|---|---|
| 3×3 점: 면적 절반 이상 남음 | 114/200 | 200/200 |
| 비스듬한 1px 흠집: 점선으로 끊김 | 94% (중앙값 5조각) | 0% |
| 비스듬한 2px 흠집: 점선으로 끊김 | 70% | 1% |
| 3px 흠집: 끊김 | 0% | 0% (변경 없음) |
| 큰 타원 결함 100개: nearest와 비트 동일 | — | 100/100 |
| 배경이 아닌 픽셀을 덮어쓴 수 | — | 0 |

복원한 얇은 선은 출력 격자에서 1~2px 폭의 연결된 선이다(1px 원본 선의 면적은 원본 면적/16의 약 5배로, 연결된 1px 출력 선이 가질 수 있는 최소 4배에 가깝다).

### 얇은 결함 학습 (`unet_resnet18`, CE + Dice, 입력 128², 25 epoch, seed 2개 평균)

합성 데이터: 512² 이미지 48/24장(4배 축소), 비스듬한 1~2px 흠집(클래스 1)과 3~5px 정사각 점(클래스 2). 예측을 512²로 확대해 **원본 해상도 정답** 기준으로 평가했다. 검출률은 정답 결함 성분 중 같은 클래스 예측과 겹친 비율이다.

| 학습 마스크 축소 | 클래스 가중치 | 흠집 검출률 | 점 검출률 | 전체 | 오검출/장 |
|---|---|---|---|---|---|
| nearest(9.33 1차) | 없음 | 0.547 | 0.000 | 0.279 | 0.00 |
| **보정** | 없음 | **0.972** | 0.000 | 0.495 | 0.04 |
| 보정 | Sqrt | 0.906 | **0.500** | **0.707** | 0.04 |

- 라벨 보정만으로 흠집 검출률이 0.55에서 0.97로 올랐다. 오검출은 늘지 않았다.
- 점 결함은 축소 후 학습 픽셀의 0.02%(139px 대 배경 783,250px)라서 가중치 없이는 한 번도 예측되지 않았다. 입력 이미지에는 점이 남아 있다(밝기 응답 최소 +15). 데이터 문제가 아니라 희귀도 문제다. Sqrt 가중치는 점을 찾게 하지만 흠집을 약간 놓친다(0.97 → 0.91). 그래서 기본값은 바꾸지 않는다. 대신 기본 모델 학습이 첫 epoch 집계에서 0.1% 미만인 결함 클래스를 찾으면 로그에 Sqrt 사용을 권한다(추가 데이터 순회 없음).
- 이런 결함을 놓치지 않는 가장 확실한 방법은 입력 크기를 키우는 것이다. 이 실험은 효과 비교용이며, 실제 데이터의 최적 설정을 보장하지 않는다.

## 호환 범위

- 기존 프로젝트를 열면 `segmentation_loss`가 없으므로 기본값 CE + Dice로 학습한다. 9.23과 같은 손실이 필요하면 학습 화면에서 CE를 선택한다. 같은 데이터라도 9.23 실행과 손실 값을 직접 비교하면 안 된다(Dice 항이 더해짐). 검증 mIoU로 비교한다.
- 학습 마스크 보정은 학습 입력 크기로 줄이는 과정에만 적용된다. 저장된 정답 PNG는 바뀌지 않는다. 얇은 결함은 출력 1~2px 폭으로 학습하므로, 원본 해상도로 되돌린 예측 면적은 실제 흠집보다 넓을 수 있다. 면적 기준 판정은 원본 해상도 기준으로 다시 확인한다.
- 9.33으로 저장한 프로젝트 파일에는 새 설정 키가 있어 9.23 이하 버전에서 열 수 없다(기존에 설정을 추가할 때와 같은 동작).
- Windows 설치본, GPU AMP 학습, 실제 생산 데이터의 정확도는 이 환경에서 확인하지 않았다.
