# 표시 버그 분석 및 검증

## 원인

1. `gui/core/spatial_preview.py`의 원본+팔레트 혼합이 배경 ID 0에도 적용됐다. 배경색이 붉은 팔레트여서 배경 비율이 높은 이미지 전체를 붉게 덮었다.
2. `gui/widgets/inference_widget.py`의 Grad-CAM 기본 체크를 분할 모델도 그대로 이어받았다. 기본으로 모델 반응 맵을 표시하여 실제 분할 영역과 혼동됐다.
3. 원본 비교는 히트맵 캐시가 있을 때만 갱신됐다. Grad-CAM이 없는 결과를 탐색하면 이전 이미지의 원본이 남을 수 있었다.

## 수정

- 원본 배경과 마스크 내부 구멍을 그대로 보존. 전경 안쪽 채움/윤곽만 표시.
- 연결된 영역별 실제 클래스명/좌표/면적 보존. Qt에서 한글 이름을 화면 레이어에 표시하며 확대/이동/썸네일 좌표를 맞춤.
- 분할 모델 로드(직접/프로세스) 및 저장 작업 복원에서 기본 Grad-CAM 해제. 반응 범위/강도 조작부는 그 보기 선택 시에만 표시.
- 원본도 임시/작업 캐시에 저장하고 표시한다. 소스 이미지가 없어져도 저장된 원본 비교가 가능하며 모델을 다시 돌리지 않는다.
- 이미지만으로도 예측 영역을 표시하며, IoU 정답 유무로 표시를 막지 않는다. 이름은 256개까지 제한하되 모든 마스크와 전체 개수는 유지한다.

## 실제 실행 확인

새 표시 회귀 11건: 배경/홀 byte 일치, 원본 배열 불변, 1px/모서리/전체 전경, 영역 개수/한글 이름, 표시 제한 시 마스크 보존, GT 없는 추론, 크롭 원본 좌표, 직접/프로세스 기본 보기, 원본 삭제 후 캐시/격자 표시, 확대/이동/초기화.

기존 회귀와 합쳐 110건 통과. Qt 화면을 실제 캡처해 한글 두 글자 이름이 생략되던 여유 폭 문제도 수정했다. 이 캡처는 알려진 마스크를 이용한 표시 검증이며 모델 정확도/처리 성능 실험이 아니다. **최종 전체 테스트: 1244 passed, 12 skipped, exit 0 (149.25초)**. `git diff --check` 통과.

## 모델별 추가 질문에 대한 확인

U-Net은 공식 ResNet18 사전학습 자산을 앱 준비 도구로 다운로드·해시검증한 뒤 1ch/3ch 모두 2 epoch 학습→best 저장→실제 로더→추론→Qt 표시를 실행했다. 합성 6/2장·64×64이므로 실행 경로 확인에 한정한다. 정확도를 보장하거나 사용자 Windows의 실패를 해결했다고 해석하면 안 된다.

SAM2는 `resolve_checkpoint_spec`에서 `SAM2 multi-graph checkpoint uses export_sam2_checkpoint`로 거부되는 것을 재현했다. `_prompt_targets`가 지정 클래스 영역을 1/0 이진 목표로 변환하고 `_sam2_logits`가 single-mask를 출력한다. DeepLab/U-Net의 클래스별 자동 semantic 출력과 같은 계약이 아니다. 예외만 없애거나 임의로 클래스 1을 붙이는 수정은 올바르지 않다. 별도 prompt UI/추론 경로 또는 클래스 구분을 학습하는 semantic 어댑터 설계가 필요하다. 이번 표시 수정에는 포함하지 않았다.

실행 기록: `artifacts/segmentation-model-audit.json`. 사용자에게 실제 실패 모델/단계/오류를 요청했다. Windows 실기와 보안 사용자 데이터는 미검증이다.
