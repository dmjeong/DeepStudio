# 15.88 회귀 오류 조사 / 15.89 수정

## 확인한 실패

15.88의 main `16fb7e4` CI 실패 로그를 기준으로 재현했다.

- 학습 화면: Dinomaly 재개용 에폭 제어를 모든 엔진에 적용해 EfficientNet 재개에서도 수정 가능했다. 기존 엔진 계약을 복원했다.
- EoMT: 보조 쿼리 손실에서 패딩된 특징을 원본 크기로 바로 줄였다. 31×45, 75×110, 640×640에서 무시 영역(255)만 덧붙여도 손실이 달라지는 것을 재현했다. 디코딩 후 원본 영역을 잘라 손실과 기울기가 모두 일치하도록 수정했다.
- Linux native 비교: Python ORT 1.31.1 / C++ ORT 1.29.0이었다. 설치 버전을 고정하고 테스트 시작 시 실제 native 버전도 대조한다. 양쪽 스레드 수도 1로 맞춘다. macOS에서는 버전 차이만으로 실패가 재현되지 않았으므로 x86 결과를 별도로 확인한다.
- 원본 크기로 복원한 anomaly float 표시 맵: OpenCV 4.10 x86 / Python OpenCV 5.0의 좌표 반올림 차이 최대 7.66e-6. 이 표시 단계에만 1e-5 범위를 적용한다. 모델/타일 스코어, 마스크 클래스 일치, 암호화 전후 일치 검사는 별도로 유지한다.
- Windows: C++ 컴파일은 성공했지만 검사 데이터 생성 Python에 ONNX가 없었다. CMake 인터프리터를 명시했다. 별도 예제는 OpenCV, 수치 회귀는 SciPy가 누락되어 설치 목록을 수정했다.
- Ubuntu 최신 이미지가 26.04로 변경되어 Playwright 1.55 설치 실패. 브라우저 작업은 24.04로 고정했다.
- 전체 검사에서 드러난 구형 테스트 대역(augmentation_info 누락), 신규 builtin_resume 미반영, 실제 원본 파일이 없는 히트맵 픽스처를 현재 실행 계약에 맞게 수정했다.

## 확인 절차

1. 기존 실패를 보존하고 전체 Python 회귀 검사를 실행한다.
2. 기본 모델 RGB/BW8 실제 사전학습 → 학습 → FP32/INT8 → 암호화 → C++ 결과를 비교한다.
3. EoMT 홀수·640 입력의 정답 좌표/기울기 및 기존 재개 화면을 별도로 검사한다.
4. 검토 브랜치에서 Linux/Windows CI를 실행하고 실패 원인을 확인한 뒤 main에 반영한다.

검증 진행 중. 최종 결과는 완료 후 갱신한다.
