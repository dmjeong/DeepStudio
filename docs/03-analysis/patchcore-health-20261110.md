# PatchCore anomaly detection 동작 점검 — 2026-11-10

기준: main `08c512b`, 로컬 버그 수정 11.60. macOS CPU 4스레드에서 확인했다. 사용자 생산 영상·Windows 장비의 성능은 확인하지 않았다.

## 실제 확인한 경로

- 공식 ImageNet ResNet18 가중치(SHA-256 `f37072fd47e89c5e827621c5baffa7500819f7896bbacec160b1a16c560e07ec`)를 앱의 기본 자산 경로로 로드.
- 앱 `PatchCoreWorker`로 합성 정상 이미지 8장으로 메모리 구축. 224×224 입력, 메모리 128×384, 이웃 수 9.
- 정상 4장·이물 4장인 별도 val에서 앱의 F1 기준 보정.
- 저장된 체크포인트를 앱 추론 엔진으로 재로드 → ONNX export → 실제 C++ C ABI로 점수·지도·판정 생성.
- 시험은 별도 정상 4장·이물 4장·3px 굵기 크랙 4장. 간단한 합성 입력이므로 생산 검출률을 대표하지 않는다.

## 재현된 배포 결함과 수정

`export_patchcore_onnx.py`의 JSON에 `input_name`이 없었다. ONNX 자체는 내보내기 검증을 통과하지만 C++ `InitializeFromJson()`은 해당 필드를 필수로 읽어 `key 'input_name' not found`로 실패했다.

실제 그래프에서 입출력 이름을 읽어 JSON에 기록하도록 수정했다. 회귀 검사는 exporter가 만든 JSON을 수정하지 않고 C++ 로더로 연다. 모델 연산·메모리·임계값은 변경하지 않았으므로 기존 체크포인트를 다시 내보내면 된다.

## 검출 결과와 남은 제품 제약

val에서 선택한 원시 이상 점수 임계값: **5.3329916**. 이물만 불량 보정에 제공했다.

| 별도 시험 | 원시 점수 범위 | NG 판정 |
|---|---:|---:|
| 정상 | 1.408–1.456 | 0/4 |
| 이물 | 5.454–5.582 | 4/4 |
| 크랙 | 4.476–4.693 | 0/4 |

크랙은 정상보다 점수가 높았지만 선택된 기준보다 낮아서 놓쳤다. 이것은 PatchCore가 모든 크랙을 못 잡는다는 뜻이 아니라, 제공된 특정 불량의 F1만 최대로 하는 임계값이 미지의 결함에 충분하지 않을 수 있음을 보이는 예다. 결과를 보고 시험셋에 맞게 임계값을 재조정하지 않았다.

추가 제약:

1. `PatchCoreWorker`는 정상만으로 메모리 구축이 가능하다. 현재 자동 OK/NG 임계값은 정상·불량 평가 데이터가 모두 있어야 설정된다. 정상만 있을 때는 `uncalibrated` 상태이며 ONNX 자동 판정 배포가 차단된다. 이는 알고리즘 자체의 필수 조건이 아니라 앱의 현재 정책이다.
2. 큰 영상을 기본 224×224로 줄인다. 중앙 크롭도 이후 224×224로 줄어든다. 3500px 폭에서 5px인 균열은 가로 기준 약 0.32px가 되므로 미세 결함 보존을 기대할 수 없다. PatchCore 전용 고해상도 타일 추론은 이 점검에서 확인되지 않았다.
3. 히트맵은 이미지별 최소·최대값으로 상대 정규화된다. 정상의 빨간 부분을 바로 불량으로 해석하거나 다른 이미지의 색 강도와 직접 비교하면 안 된다.
4. 점수는 정상 특징으로부터의 거리다. 0~1 표시 값도 불량 확률이 아니다. `crack`, `FM` 등의 불량 종류를 구분하는 다중 클래스 모델은 아니다.
5. val이 적합하지 않으면 test를 보정에 사용할 수 있다. 이때 화면 평가값은 독립 시험 성능이 아니다.

## 검증 범위

- 기존 PatchCore 데이터·학습·추론·점수·내보내기·모델 관찰 테스트 34개 통과.
- 실제 ResNet18 시험 12장에서 PyTorch↔ONNX 점수 최대 절대 차이 약 `4.2e-6`, 지도 약 `3.7e-5`, OK/NG 모두 일치.
- 수정 후 같은 산출물을 C++ C ABI로 로드하고 12장의 판정이 일치하는 것을 확인.
- 새 native 회귀 8개: 현재/이전 점수, 전체/중앙 크롭, 학습 이미지/새 입력의 조합. C++ 지도와 Python ORT 지도 일치, PyTorch 점수 일치 및 새 입력의 PyTorch 지도 일치.
- 학습 이미지와 메모리 특징이 거의 같은 경우 FP32 제곱 거리 계산의 상쇄로 무작위 ResNet18 fixture의 PyTorch↔ORT 지도 오차가 약 0.0063까지 나타났다. 점수/판정은 일치했다. 이 경우까지 지도 수치가 엄격히 일치한다고 주장하지 않는다. 테스트는 같은 ONNX 그래프의 Python↔C++ 일치와 모델 변환의 수치 차이를 구분한다.
- Wide-ResNet50-2의 실제 사전학습 검출 성능, 사용자 영상, Windows 실행은 이번 실험에서 검증하지 않았다. Windows/Linux CI에 native 회귀를 추가했으며 원격 실행 전이다.

## 필요한 후속 설계

정상 이미지 학습 → 학습에서 제외한 정상 이미지로 허용 범위 보정 → 독립적인 정상·불량 시험 → 고정한 기준으로 운용 순서가 필요하다. 정상 표본이 적으면 최대 점수를 기준으로 해도 이후 오검출률을 보장할 수 없다. 정상 기준과 불량을 이용한 F1 기준을 별도 정책으로 표시하고, 타일/칩 ROI에서 작은 결함을 보존한 뒤 원본 좌표로 지도를 합치는 경로가 다음 개선 대상이다.
