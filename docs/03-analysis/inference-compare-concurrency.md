# 13.86 검증 — 원본 비교 및 복수 앱 CPU 추론

2026-11-11 / macOS / Python 3.12 / PySide6 / 실제 CPU 자식 프로세스.

## 재현된 원인

1. `InferenceWidget._display_numpy_image`는 Grad-CAM 캐시가 있을 때만 왼쪽 원본을
   갱신했다. 반응 맵이 없는 결과를 연속 표시하면 오른쪽은 새 이미지 결과인데 왼쪽은
   이전 이미지였다. 프로젝트를 비울 때도 왼쪽 pixmap이 남았다.
   수정 전 자동 검사에서 빨간 첫 이미지가 녹색 두 번째 이미지의 원본 칸에 남는 실패를 확인했다.
2. `JobManager.require_idle`과 `run_job`은 작업 종류/장치와 무관하게 공유 compute.lock을
   사용했다. 다른 앱의 학습이 CPU 모델 확인과 추론까지 막았다.
3. `JobManager.__init__`은 이전 기록의 running 상태를 모두 중단 처리했다.
   다른 앱/워커가 살아 있는지 검사하지 않았다.
4. 프로젝트 저장은 원자적 파일 교체만 했고, 다른 앱이 이미 수정한 파일인지 검사하지 않았다.
   변경 없는 저장도 modified를 바꾸어 실행 중 학습의 변경 감지에 걸릴 수 있었다.

## 수정 및 검사

- 모든 태스크의 반응 맵 없는 표시, 비교 on/off, 프로젝트 비우기, 없는 파일 검사.
- 다른 폴더의 같은 파일명, 배치 표 역순 정렬, 결과 재선택, 원본 파일 교체 후 저장된 원본 복원.
- 캐시에 다른 이미지 경로의 반응 맵이 들어오면 저장 거부.
- 실제 CPU 분할 추론 프로세스 두 개를 동시에 실행. 외부 학습용 compute.lock을 잡은 상태에서도
  모두 완료했고 각 작업의 원본 배열이 해당 입력과 픽셀 단위로 일치했다.
- 실제 MainWindow 프로세스 두 개를 함께 실행해 둘 다 준비 상태 유지, 종료 코드 0 확인.
- 살아 있는 다른 앱 기록 유지, PID 재사용 구분, 타 앱 실행 기록 삭제/압축 거부, 완료 상태 갱신.
- 잘못된 요청 파일 생성 실패를 failed로 기록하고 다음 실행 슬롯 해제.
- 프로젝트 무변경 저장 시 파일 내용·수정 시각 불변. 새 학습 기록이 추가된 파일을 이전 창에서
  저장하면 거부. modified 값을 바꾸지 않은 외부 편집도 SHA256으로 감지.
- Windows 저장 시 LF를 명시해 텍스트 줄바꿈 변환으로 저장한 해시와 실제 파일이 달라지지 않게 했다.
