# PatchCore 검출 품질 진단 — 2026-11-10

## 결론

3504×1504 합성 트레이를 224×224로 줄이는 조건에서는 메모리를 31개에서 1,024개로 늘려도 미세 크랙·이물을 검출하지 못했다. 같은 메모리 크기로 원본 해상도를 유지하는 타일 검사에서는 분리력이 크게 나아졌다. 다만 정상 오검출과 결함 누락이 남고 Python CPU 실행 시간이 약 1.16초이므로 제품 해결 완료로 볼 수 없다.

이는 합성 데이터와 ResNet18의 통제 실험이다. 사용자 생산 영상, 다른 백본, Windows/C++ 실행의 검출률을 측정한 결과가 아니다. 현재 사용자의 입력이 이미 칩 단위로 잘려 있다면 전체 트레이 축소 문제를 사용자 원인으로 단정할 수 없다.

## 실험 설계

- 기존 합성 생성기: `runs/crack-fm-evaluation-20261102/results/execution_source/tools/make_crack_fm_trays.py`.
- 영상: RGB 3504×1504, 8×16칩, 원근·곡면형 왜곡과 조명 변화 포함.
- 정상 학습 4장: 독립 seed 77000–77003. 기존 불량 포함 train 영상은 사용하지 않았다.
- 임계값 설정: 결함 포함 val 2장, 별도 normal_calibration 2장.
- 독립 시험: test 4장, 크랙 예시 윤곽을 합성한 real_shape_test 2장, normal_test 4장. real_shape_test도 실제 생산 영상이 아니다.
- 시험 칩: 정상 1,256개, 크랙 16개(무작위 호 8개·예시 윤곽 8개), 이물 8개.
- 백본: 공식 ImageNet 사전학습 ResNet18. 가중치 SHA-256 `f37072fd47e89c5e827621c5baffa7500819f7896bbacec160b1a16c560e07ec`.
- 증강 없음, 코어셋 seed 0, 후보 최대 20,000개.
- 전체 축소 전처리는 앱 `patchcore_data.input_tensor`와 수치가 정확히 같은지 확인했다.
- 타일: 원본 픽셀 224×224, 간격 192px, 끝 경계에 마지막 타일 배치. 원본 한 장당 152개. 배치 8개, Hann 가중치(최솟값 0.01)로 지도 병합, 전 픽셀 덮임 확인.
- 칩 점수: 원본 좌표로 복원한 이상 지도에서 정답 칩 영역의 최댓값. 정답 칩 영역은 **평가용으로만 사용한 이상적 ROI**이며 자동 칩 위치 검출의 성능은 포함하지 않는다.
- 이 점수는 앱의 기존 전역 이미지 재가중 점수와 다르다. 앱 판정 성능을 그대로 재현했다고 주장하지 않는다.
- 시험셋을 보고 임계값이나 모델 설정을 다시 맞추지 않았다. 모델 seed 반복과 신뢰구간 추정은 수행하지 않았다.

## 결과

정상 조정 영상에서 관측한 최대 점수보다 큰 값(`nextafter`)을 임계값으로 삼았다. 조정셋 오검출 0은 새로운 영상에서 오검출 0을 보장하지 않는다.

| 입력 방법 | 저장 특징 수 | 크랙 검출 | 이물 검출 | 정상 오검출 |
|---|---:|---:|---:|---:|
| 전체 224×224 축소, 코어셋 1% | 31 | 0/16 | 0/8 | 26/1,256 |
| 전체 224×224 축소, 저장량 증가 | 1,024 | 0/16 | 0/8 | 0/1,256 |
| 원본 해상도 타일 | 1,024 | 15/16 | 8/8 | 3/1,256 |

검증셋 F1 최적 기준도 별도로 시험했다. F1은 `gui/core/metrics.py`의 `AnomalyMetrics`로 계산했지만, 입력 점수는 위 칩 점수다.

| 입력 방법 | 검증 F1 기준값 | 크랙 검출 | 이물 검출 | 정상 오검출 |
|---|---:|---:|---:|---:|
| 전체 축소, 31개 | 2.265757 | 2/16 | 0/8 | 119/1,256 |
| 전체 축소, 1,024개 | 1.722826 | 5/16 | 1/8 | 158/1,256 |
| 타일, 1,024개 | 3.146308 | 8/16 | 7/8 | 0/1,256 |

타일에서 F1 기준은 정상 오검출을 줄였지만 크랙 8개와 이물 1개를 놓쳤다. 정상 기준으로 낮추면 크랙은 15개, 이물은 8개 검출하지만 정상 3개가 NG가 된다. **임계값 조절만으로 누락과 오검출을 동시에 없애지 못했다.** 시험 결함 24개만으로 운영 검출률을 추정해서는 안 된다.

## 속도와 학습량

Apple M4/macOS, PyTorch CPU 4스레드, OpenCV 1스레드. 각 시험 영상 한 번씩 측정한 중앙값이며 정식 반복 벤치마크가 아니다. 영상 파일 디코딩과 칩 점수 집계는 제외하고 전처리·모델·지도 복원을 포함한다. ONNX/C++ 시간은 측정하지 않았다.

| 입력 방법 | 특징 추출 | 코어셋 선별 | 전체 fit | 시험 추론 중앙값 |
|---|---:|---:|---:|---:|
| 전체 축소, 31개 | 0.198초 | 0.0019초 | 0.200초 | 7.80ms |
| 전체 축소, 1,024개 | 0.197초 | 0.0193초 | 0.217초 | 8.72ms |
| 타일, 1,024개 | 4.404초 | 0.0745초 | 4.815초 | 1,164.56ms |

타일에서는 원시 특징 476,672개 중 후보 20,000개를 남긴 뒤 1,024개를 선택했다. 전체 축소는 원시 특징 3,136개다. 따라서 타일 비교는 저장 특징 수만 같고, 관측 해상도·원시 특징 수·후보 제한 효과가 달라진다. 이 실험의 목적은 같은 저장 용량에서 입력 처리 경로의 효과를 확인하는 것이다.

## 코드에서 확인한 이유

1. `python/patchcore_data.py::input_tensor`는 전체 영상 또는 중앙 크롭을 정사각형 입력으로 축소한다. 가로 3,504px에서 3px 폭은 가로 성분 기준 224px 입력에서 약 0.19px다. 방향과 보간에 따라 흔적은 남을 수 있으나 형태 정보가 크게 줄어든다.
2. `python/patchcore.py::PatchCoreBackbone`은 layer2/3 특징을 사용한다. 224px 입력에서 기본 특징 격자는 28×28이다. 128칩을 한 입력에 넣으면 칩별 국소 정보가 매우 제한된다.
3. 코어셋은 이미 추출한 정상 특징 중 대표를 고르는 단계다. 입력에서 사라진 결함을 저장량 증가로 복구하지 못한다. 이번 실험에서 이를 직접 확인했다.
4. 검증 결함의 F1을 최대로 하는 기준이 다른 모양의 크랙을 충분히 검출한다는 보장은 없다. 정상만으로 정한 기준 역시 정상 변동 표본이 적으면 새로운 정상에 오검출한다.

## 제품 개선 우선순위

1. 칩 ROI 또는 타일을 학습·평가·추론에 동일하게 적용하고, 원본 좌표 복원 계약을 체크포인트·ONNX JSON·C++까지 연결한다. 기존 모델에 추론 타일만 켜지 말고 같은 전처리로 정상 메모리를 다시 구축해야 한다.
2. 임계값 정책과 정상 조정셋을 분리한다. 독립 정상 시험의 오검출, 결함 시험의 누락을 함께 표시하고 시험셋을 보정에 자동 재사용하지 않는다.
3. 정확도를 고정한 뒤 타일 배치, 특징 추출과 최근접 탐색 비용을 분리 측정한다. 타일 구현이 1초/100ms 목표를 충족한다고 미리 약속하지 않는다.
4. 충분한 정상 변동을 포함해도 크랙 점수와 정상 점수가 겹치면 미세 특징 계층·ROI 정렬을 비교한다. 그래도 분리되지 않으면 라벨 기반 분할과의 비교가 필요하다. 증강·코어셋 비율만 계속 올리는 방식은 근거가 부족하다.

이 문서는 진단 결과다. 타일 기능을 앱 또는 C++에 통합하지 않았고, 관련 제품 설정도 변경하지 않았다.
