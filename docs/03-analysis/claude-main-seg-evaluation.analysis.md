기준: main `fe6782e`, Claude 최신 `04348c4` (`with-evision` 브랜치 `e49c7c2` 포함).

## 설계 대조

| 항목 | 구현·확인 |
|---|---|
| 두 브랜치 기능 보존 | 기존 `dinov2_vits14` 체크포인트와 신규 `_cls`/`_seg` ID 분리. 원본 전경 표시·정답 IoU와 Claude 결함 판정 UI 공존 |
| 실제 배포와 동일한 C++ 경로 | `VisionInference::Segment` 사용. 모델 JSON의 전처리·크롭·전체 영역·결함 규칙 적용 |
| 명령행 인자 없는 실행 | EXE 옆 `evaluation.json`, JSON 위치 기준 상대 경로, 모델 1회 초기화, 입력별 워밍업 |
| 원본 정답 계약 | 원본 크기 단일 채널 ID PNG, 255 무시, `valid_mask` 검사 영역만 집계. 정답 누락·크기 오류·미등록 ID·평가 픽셀 없음 거부 |
| 지표 계산 | 전체 데이터 혼동행렬 합산, IoU/Dice, 배경 포함/제외 평균. 정답·예측 모두 없는 클래스 제외, 정답 없이 오검출된 클래스 포함 |
| 실행·회귀 검증 | 실제 7개 모델 구조 export→C++ 평가, Python 픽셀 집계 일치, 결함 규칙 Python/C++ 일치, native 배포·암호화 계약 |

설계 구현 6/6. Windows 실행 및 대상 CPU 성능 확인은 별도의 환경 검증이며, 로컬 통과로 대체하지 않는다.

## 통합 시 수정한 문제

- 동일 DINOv2 이름에 서로 다른 디코더가 연결될 위험을 제거했다. 기존 main 체크포인트를 새 구조로 잘못 읽지 않는다.
- 부분 가중치 준비·수동 가져오기를 허용하면서 공식 해시·manifest 손상 검사는 유지했다. ResNet50의 다운로드 주소를 V2 가중치 파일명과 일치시켰다.
- 새 프로젝트가 배경을 자동 추가하는 규칙과 오래된 프로젝트 복구 테스트를 구분했다. 배경은 지우개로 편집하며, 결함으로 그리는 항목으로 활성화하지 않는다.
- 심볼릭 링크 영상의 실제 대상 경로가 정답 탐색에 섞이던 예제 오류를 수정했다. 데이터셋 안의 상대 파일명을 유지한다.
- 평가 보고서는 이미지와 CSV가 모두 저장된 후 최종 이름으로 공개한다. 오류를 정상·100% 점수로 바꾸지 않는다.
- INT8 비교 도구가 읽기·추론 실패 영상을 건너뛰고 성공하던 경로를 차단했다. 모델끼리 일치한 것을 정답 기반 정확도 합격으로 표시하지 않는다.
- Windows 워크플로의 C++ 배치 검사를 실제 SDK를 준비하는 job으로 옮겼다. C# job에는 `EXAMPLE_DEPS`가 없어 기존 위치에서는 실행할 수 없었다.

## 범위와 한계

단일 semantic logits ONNX 평가를 지원한다. SAM2 프롬프트 encoder/decoder는 기존 별도 SDK API를 사용한다. 암호화 모델은 키 전달 초기화 API가 필요하며 이 폴더의 예제는 평문 ONNX 평가이다.

7개 구조 테스트는 결정론적 무작위 가중치로 연결·좌표·계산을 검증한다. 정확도는 이전에 합성 트레이로 학습한 U-Net Lite 1개를 별도로 평가했다. 비공개 검사 데이터, Windows/i7 정확도·성능, 모든 공식 사전학습 가중치의 재학습을 확인했다는 뜻이 아니다.
