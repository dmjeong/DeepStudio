## 발견하고 조치한 사항

1. ONNX trace에서 위치 임베딩의 scale factor가 Tensor로 변하는 문제를 발견했다.
   배포 계약인 고정 공간 크기를 Python 정수로 고정하고, 배치 차원은 계속 동적으로 유지했다.
2. DINOv2에 ImageNet 가중치라는 안내가 표시되지 않도록 LVD-142M 명칭을 분리했다.
3. 새 디코더와 detail 경로가 backbone freeze 옵션에 함께 동결되지 않도록 optimizer의
   head 파라미터 그룹에 포함했다. 클래스 재정의 때 마지막 head만 재초기화한다.
4. 공식 사전학습 + 12에폭 + 가중치 보정 없음의 합성 학습에서 배경 편향이 남았다
   (mIoU 0.3075). 이 결과도 원본 artifact에 보존했다. balanced + 40에폭에서는
   흑백 0.9906 / 컬러 0.9967을 얻었다. 두 설정을 동시에 바꿨으므로 개선을
   한 설정의 효과로 단정하지 않는다. 실제 검사 정확도 개선이라는 의미도 아니다.
5. CPU 측정 결과 U-Net보다 느렸다. 속도 개선 기능이라고 표시하지 않는다.

## 실제 측정

Apple M4, macOS 26.5 ARM64, Torch 2.14.1, ORT 1.29, 4스레드,
392×392, batch1, 워밍업 5회·측정 20회. 메모리 uint8 입력의 리사이즈/정규화/
ORT 실행/argmax 포함. 디스크 읽기, 카메라 취득, UI 렌더링 제외.

| 모델 | median | p95 |
|---|---:|---:|
| DINOv2 + Detail, 1ch | 87.84ms | 91.96ms |
| DINOv2 + Detail, 3ch | 85.82ms | 87.03ms |
| U-Net ResNet18, 1ch 참고 | 39.18ms | 39.86ms |

DINOv2 분할 헤드는 96×96 합성 데이터로 학습했다. 392×392 측정은 다른 입력 크기에서의
연산 비용/ONNX 수치 비교용이며 그 해상도의 학습 정확도 평가가 아니다. U-Net은 공식
ResNet18 백본과 무작위 decoder를 사용했다. 모델 간 정확도 비교나 Windows i7 성능 추정에
사용하지 않는다. 이 측정에서 원본 128칩 전체 20ms 달성을 주장할 근거는 없다.

## 남는 한계

- 실제 공정 데이터, Windows i7, CUDA 학습, C# 관리 런타임 실행은 이 환경에서 미검증.
  C#이 사용하는 C ABI의 실제 마스크 결과는 별도로 확인했다.
- DINOv2 백본 패치 크기는 여전히 14다. detail 경로 추가가 작은 결함의 보존을 보장하지
  않으며, 앱에서 이미지를 과도하게 축소하면 사라진 정보는 복원되지 않는다.
- SAM2의 기존 자동 semantic inference 경로 문제는 별도 건이다. 이 추가로 해결됐다고
  주장하지 않는다.
