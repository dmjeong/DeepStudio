# 21.57 원본 크기 학습

데스크톱 **학습 → 학습 이미지 → 원본 크기로 학습**을 켜세요. 학습 이미지가 2048×2048이면 한 장의 2048×2048 픽셀을 한 번에 입력합니다. 일반 입력 크기와 패치 설정은 비활성화됩니다. 학습·검증에는 가로와 세로가 각각 같은 이미지가 필요합니다. 중앙 크롭을 지원하는 모델은 공통 크롭을 지정해 그 안의 원본 픽셀만 사용할 수 있습니다.

| 태스크 | 적용 범위와 입력 처리 |
|---|---|
| 분류 | EfficientNet B0/B1, ResNet, ConvNeXt, DINOv2, LibreYOLO MobileNetV4, Custom CSP가 직사각형 입력을 사용합니다. |
| 객체 탐지 | Custom CSP, LibreYOLO YOLO9·D-FINE, RE-DETRv4 S/M/L가 이미지와 정답 박스를 같은 배율로 유지합니다. YOLO9은 보폭에 맞게, D-FINE과 RE-DETRv4는 정사각형이 되도록 오른쪽과 아래에 여백을 채웁니다. 배포한 모델은 원본 기준 좌표를 반환합니다. |
| 분할 | U-Net 계열, DeepLab, BiSeNetV2, STDC, EfficientViT, SCTNet, EoMT, DINOv2, SegFormer, Mask2Former, Custom CSP가 전체 판정 영역을 사용합니다. 필요한 가장자리 여백은 분할 정답에서 제외합니다. SAM2.1 Hiera 4종은 같은 크기의 원본 이미지와 마스크를 사용합니다. SAM2 원본 모드에서는 중앙 크롭을 끄세요. |
| 이상검출 | PatchCore, Dinomaly와 Custom CSP 재구성이 원본 판정 영역으로 학습합니다. PatchCore는 정상 이미지의 특징을 메모리 뱅크에 수집합니다. |

**추론과 배포.** 새 학습의 Best 체크포인트에 원본 가로·세로가 저장됩니다. 추론에는 같은 크기의 이미지 또는 프로젝트에서 설정한 중앙 크롭을 포함하는 원본을 넣으세요. 내보낸 ONNX와 JSON을 함께 배포하고 C++·C#에서는 이 버전의 SDK를 사용하세요. Euresys BW8 분류 예제를 복사해 쓰는 프로젝트는 `classifier.h`와 `bw8_preprocess.h`를 함께 갱신하세요. 이전 SDK는 새 JSON의 원본 크기 정보를 무시하고 다른 크기의 이미지를 리사이즈할 수 있습니다. 예전 체크포인트는 기존의 입력 규칙을 따릅니다.

**메모리.** 입력 면적과 모델이 내부에 채우는 여백에 따라 GPU 메모리 사용량이 달라집니다. 2048×2048 교사 학습은 우선 배치 1과 GPU 혼합 정밀도(AMP)로 시작하세요. 모델이 큰 경우 이 설정에서도 장비별 메모리 확인이 필요합니다.

**Mask2Former 후보 수.** **학습 → 하이퍼파라미터 → 마스크 후보 수**에서 새 학습의 쿼리 수를 바꿉니다. 기본값은 100이고 예를 들어 16을 지정할 수 있습니다. 이어학습과 배포에는 해당 체크포인트에 저장된 값을 사용합니다.

### 확인한 실행

- 데스크톱 모델 카탈로그 39종에서 원본 크기를 선택하고 프로젝트 설정에 저장되는지 자동 검사했습니다.
- 직사각형 합성 이미지로 SAM2 이외 기본 분할 모델 18종을 각각 한 에폭 학습한 뒤, FP32 ONNX를 C++17에서 열어 마스크를 Python ONNX Runtime 결과와 픽셀별로 대조했습니다. SegFormer B2는 같은 이미지로 FP16과 정적 INT8도 대조했습니다.
- SAM2.1 Hiera Tiny는 공식 가중치에서 2048×1024와 2048×2048로 미세조정했습니다. 2048×1024 모델은 두 ONNX 그래프를 C++에서 불러 점 프롬프트로 마스크를 얻었습니다. Small·Base+·Large는 공식 모델 구성과 무작위 초기 가중치로 269×145 직사각형의 한 에폭 학습·검증을 확인했습니다.
- LibreYOLO 분류 2종과 탐지 5종은 홀수 크기의 직사각형으로 각각 학습하고 체크포인트와 FP32 ONNX를 다시 열었습니다. PatchCore와 Dinomaly는 79×51 판정 영역에서 ONNX와 C++ 추론을 실행했습니다.

검증 환경은 macOS ARM CPU입니다. Windows GPU에서의 최대 배치, 검사 데이터의 클래스별 IoU, 설비 CPU의 처리시간은 별도로 측정해야 합니다.
