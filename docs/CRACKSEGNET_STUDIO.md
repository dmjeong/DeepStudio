# CrackSegNet Studio

분할 프로젝트의 **학습 → 모델 → CrackSegNet Studio**에서 선택한다. 기본 제공되는
자체 구현이며 Docker나 추가 모델 팩은 필요 없다. 공식 사전학습 가중치는 확인되지
않았으므로 **처음부터 학습**, **이전 Studio 학습 결과(.pt)로 추가 학습**, **중단한 학습 재개**를 제공한다.
다른 U-Net이나 동명의 옛 CrackSegNet 가중치를 넣는 모델이 아니다.

## 무엇을 구현했나

참고: Anbin Yu, Wensheng Mei, Dapeng Zhu,
[A Dual-Stage Deep Learning Framework for Fine-Crack Segmentation in High-Resolution UAV Images for Bridge Inspection](https://doi.org/10.3390/rs18213712),
Remote Sensing 18(21), 3712 (2026).

저자의 코드·가중치를 가져온 구현이 아니다. 공개 논문 설명을 참고해 Studio의 다중 클래스
마스크 학습 및 ONNX 배포 계약에 맞춰 직접 작성했다. 이름은 `CrackSegNet Studio`,
내부 모델 ID는 `cracksegnet`, 구현 버전은 `cracksegnet_studio_v1`이다.
논문의 점수·실행 속도를 이 모델의 성능으로 표시하지 않는다.

| 부분 | Studio 구현 |
|---|---|
| 입력·출력 | RGB/BW8 입력, 배경 포함 프로젝트 클래스별 로짓. 출력 크기는 입력과 동일 |
| 인코더 | 폭 16→24→48→96→160→256, PixelUnshuffle 5회 |
| 블록 | 1×1·3×3·팽창 합성곱 가지, 잔차 연결, 채널·공간 주의(CBAM) |
| 변형 합성곱 | 마지막 인코더 2개·첫 디코더 2개 블록. 학습한 위치에서 bilinear sampling |
| 주변 특징 연결 | 최하단 격자의 이웃 8개+자신에 대한 그래프 주의 2층(각 128채널), 위치·거리·각도 특징 |
| 디코더 | PixelShuffle 5회와 같은 크기 인코더 특징 연결 |
| 학습 손실 | 앱의 다중 클래스 CE / CE+Dice, 클래스 가중치 None / Sqrt / Balanced |
| 파라미터 | 3채널·배경 포함 3클래스에서 1,239,424개 |

픽셀 재배열 자체는 픽셀을 버리지 않지만 이후 학습된 합성곱은 특징을 압축한다.
미세 결함 보존이나 검출률 개선을 수학적으로 보장하는 구조는 아니다. 원본 크기가
32의 배수가 아니면 오른쪽·아래를 채웠다가 출력에서 자르며, 모델 안에서 입력을 축소하지 않는다.
앱에서 설정한 입력 크기/판정 영역/패치 배율에 따른 전처리는 별도로 적용된다.

## 원 논문과 다른 부분

- 논문의 1차 CrackClsNet 후보 선별기를 사용하지 않는다. 선택한 판정 영역 전체를 검사한다.
- 선택된 192px 패치들의 겹친 특징을 합쳐 만드는 가변 그래프 대신, 각 입력의 병목 특징 격자에서 지역 그래프를 구성한다.
  서로 다른 추론 타일 사이에는 그래프 연결이 없다. 타일 결과는 기존 겹침/가중 합성 경로로 합친다.
- 채널 폭, 잔차 블록 구성, 출력 헤드와 손실은 Studio 설계다. 논문의 정확한 재현이 아니다.
- 그래프 자체 연결의 위치 특징은 0이며, 경계 밖 이웃은 제외한다.
- PyTorch Geometric이나 CUDA 전용 변형 합성곱 대신 표준 PyTorch/ONNX 연산으로 작성했다.

## 학습·배포

1. Segmentation 프로젝트에 배경과 결함 클래스를 등록하고 픽셀 마스크를 준비한다.
2. `CrackSegNet Studio → 처음부터 학습`을 고른다. 작은 결함은 우선 입력 256 또는 384,
   패치 배율 100%, CE+Dice·Sqrt로 기존 모델과 비교한다. 이것은 시작 설정이지 검증된 최적값은 아니다.
3. 원본 크기 학습과 패치 학습은 기존 앱처럼 둘 중 하나만 선택한다.
   CBAM이 창 전체의 특징을 사용하므로 패치로 학습했다면 추론·보정도 학습한 크기의 타일을 사용한다.
4. Best 체크포인트로 검증·시험 영상의 클래스별 IoU, 미검, 작은 오검을 확인한다.
   정상 영상과 다른 로트의 시험 영상을 포함하고, 비교 모델과 동일한 분할·판정 기준을 쓴다.
5. 내보내기에서 FP32 / FP16 / INT8을 선택한다. **opset 17 권장, 최소 16**이다.
   INT8은 보정 영상을 지정하고 생성된 비교 보고서와 실제 시험 결과를 확인한다.
6. 암호화 내보내기도 기존 키·`.dvsenc` 경로를 그대로 사용한다.

FP16은 입출력이 FP32이며, 좌표 정밀도를 위해 변형 합성곱 가지는 FP32로 보존한다.
INT8은 Conv 등의 일부 연산을 양자화하고 GridSample 등은 부동소수점으로 남는 혼합 그래프다.
어느 변환도 더 빠르거나 정확도가 같다고 자동 보장하지 않는다. 특히 이 모델은 주변 특징 연결과
sampling 비용이 있으므로 U-Net Lite보다 빠르다고 볼 수 없다. 목표 Windows CPU에서 비교해야 한다.

다른 학습된 분할 모델의 `.pt`를 교사로 사용하는 기존 지식 증류 경로를 사용할 수 있다.
교사·학생의 클래스 순서, 입력 채널, 정규화 계약은 일치해야 한다. 교사로 쓸 때도 먼저 직접 학습한다.

## C++ 사용

별도 CrackSegNet 플러그인이나 사용자 정의 ONNX 연산 DLL이 필요 없다.
[분할 C++ 예제](../example/cpp/dense_models/README.ko.md)의 `VisionInference::Segment()`와
[정답 마스크 평가 예제](../example/cpp/segmentation_eval/README.ko.md)를 사용한다.
FP32/FP16/INT8 모두 대응하는 JSON과 ONNX를 함께 배포한다. 암호화 모델은 `.dvsenc`와 키를 사용한다.
분류용 `with_evision/classifier.h`로 분할 모델을 읽는 방식은 아니다.

`cpp/tests/onnx_tensor_probe.cpp`는 이미 전처리된 FP32 텐서를 받는 수치 회귀 검사 도구다.
실제 영상 전처리·마스크 판정은 위 분할 예제를 사용한다.

## 출처 및 검증 범위

신규 모델 소스는 직접 작성했으며, 논문 도표·저자 코드·가중치·학습 데이터를 배포하지 않는다.
사용하는 PyTorch·ONNX Runtime 등 기존 의존성 고지는 [THIRD_PARTY_NOTICES](../THIRD_PARTY_NOTICES.md)를 따른다.
논문의 공개 라이선스가 별도 소스나 가중치 이용 허가라고 해석하지 않는다.

회귀 검사: `tests/test_cracksegnet.py`. 변형 합성곱의 출력·기울기를 torchvision 연산과 비교하고,
경계 밖 그래프 연결 제외, BW8/RGB·홀수 크기·배치 1 역전파, CPU AMP, 체크포인트 복원,
UI 등록, 합성 결함 학습, 재개·전이, 원본/패치 배포, ONNX 3정밀도 및 암호화 C++ 실행을 검사한다.
합성 데이터는 코드 연결 검사용으로, 실제 크랙 검출 성능의 증거가 아니다.
