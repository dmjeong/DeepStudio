**Deep Vision Studio 24.8: EfficientNet의 실제 1채널 입력**

23.8은 흑백을 외부에서 1채널로 받았지만 내부에서 채널별 RGB 정규화를 수행해 3채널 첫 Conv에 전달했다. 새 1채널 학습 구조와 버전별 복원 계약을 추가하므로 기능 버전 정책에 따라 23.8에서 24.8로 올린다.

- 새 EfficientNet B0/B1의 1채널 모드는 입력 `[N,1,H,W]`, 첫 Conv 가중치 `[32,1,3,3]`이다. forward에서 RGB 확장을 하지 않는다.
- 공식 RGB 사전학습 가중치의 첫 Conv는 입력 채널 방향 합산으로 초기화한다. 나머지 백본 가중치는 유지하며 사용자 분류기는 새로 초기화한다. 이 초기화는 완성된 모델의 정확도 보장이나 기존 흑백 어댑터 모델과의 전체 출력 동일성 보장을 뜻하지 않는다.
- 신규 프로젝트 및 데스크톱 생성 화면 기본값을 1채널로 설정한다. 명시적으로 저장된 3채널 설정은 유지한다. 입력 채널 필드가 없던 구형 프로젝트도 과거 기본값 3을 유지한다.
- 학습 데이터, 검증 subset, GUI 추론, Python ONNX 파일 추론, C++ 파일 추론과 데모에서 흑백 파일을 RGB로 확장했다 되돌리는 경로를 제거한다. 컬러 파일을 흑백 모델에 넣는 경우 기존 OpenCV `cvtColor` 계산을 유지한다. 입력 파일 디코딩의 기존 8비트 정책은 그대로다.
- Python `predict_gray()`는 uint8 `[H,W]` 또는 `[H,W,1]`을 직접 받으며 3채널 모델에 잘못 연결하면 거부한다. C++ `Classify()`에는 `CV_8UC1`을 직접 전달한다.
- 외부 채널 수와 첫 Conv 채널 수, 모델 구현 버전, 입력 변환 방식을 체크포인트 및 배포 JSON에 기록한다. 충돌하는 메타데이터나 실제 첫 Conv 가중치는 거부한다.
- 구형 버전 1 체크포인트의 추가 학습, 재개, 추론, ONNX 내보내기는 기존 RGB 확장 구조를 유지한다. 로그와 모델 정보에 `입력 1ch / 첫 Conv 3ch (구형 RGB 확장 모델)`로 구분한다. 기존 모델의 예측이 달라질 수 있는 구조 변환을 자동 수행하지 않는다.

새 1채널 Conv 모델을 사용하려면 입력 채널 1을 선택하고 EfficientNet ImageNet 사전학습으로 학습한 뒤 ONNX와 JSON을 함께 내보낸다. 기존 3채널 stem 체크포인트의 파일명이나 메타데이터만 변경해서는 새 모델이 되지 않는다.

Python 배포 시 `python/onnx_classifier.py`, `python/opencv_preprocess.py`, `python/center_crop.py`, `python/efficientnet_contract.py`와 내보낸 모델 쌍을 가져간다. C++은 업데이트한 헤더와 소스로 재빌드한다. 상세 사용법은 [EFFICIENTNET.md](EFFICIENTNET.md)를 따른다.

입력 버퍼 재사용과 선택 이미지 Grad-CAM은 별도 설계 상태다. 이번 1채널 수정에 포함되어 구현 완료된 기능으로 보고하지 않는다.

로컬 Python 회귀 검사는 124개 중 102개 통과, 22개 의존성 누락으로 건너뜀이며 웹 로직 검사는 11개 통과했다. Python 문법 검사와 diff 공백 검사도 통과했다. 채널 계약, 실제 가중치 형태 충돌, 구형 프로젝트 보존, 첫 Conv 가중치 합산의 NumPy 수치 비교를 포함한다.

실제 실행용 회귀 검사는 공식 torchvision의 첫 Conv를 동일한 1채널 구조로 맞춘 B0/B1 비교, gradient 갱신, 체크포인트 복원, GUI 입력 관찰, ONNX 외부 입력과 첫 Conv 검사, C++ JSON 및 흑백 파일 추론을 포함한다. 이 환경에는 Torch, OpenCV 및 ONNX Runtime이 없어 해당 실제 모델 실행 검사는 실행하지 못했다. 전체 Qt 화면, C++ 빌드, 프런트엔드 빌드와 실제 정확도 및 속도는 미검증이다. CI 실행 결과와 태그 생성은 별도로 확인해야 한다.
