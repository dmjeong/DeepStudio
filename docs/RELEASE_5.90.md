# 5.90 — 분류 판정·속도를 함께 검증하는 FP32 배포

## 변경 이유

기존 방식은 임의/zero 입력의 로짓을 비교해 실패하면 전체 FP64를 사용했다.
분류 판정이 같은 경우에도 숫자 기준 때문에 느린 파일로 전환되었으며, 실제 이미지와
전·후처리를 포함한 성능을 합격 기준에 연결하지 못했다.

## 사용

EfficientNet 프로젝트의 ONNX 내보내기에서 '실제 이미지로 FP32 분류 검증'을 사용한다.
비교 이미지 폴더는 클래스별 하위 폴더를 포함해야 한다. 앱은 모든 클래스 이미지가 있는
val, test, train 폴더 순으로 연결하고 경로를 화면에 표시한다. 학습 폴더를 사용했다면
학습과 독립된 정확도 평가를 뜻하지 않는다. 이는 원본과 배포 모델의 변환 일치 검사다.

CLI에서도 `--validation-dir <클래스별 이미지 폴더>`를 사용할 수 있다.
웹 화면에도 같은 옵션을 연결했다. 비교 경로를 비우면 프로젝트의 모든 클래스가 있는
val, test, train 폴더 순으로 검사하며, 선택 경로와 처리시간을 작업 로그에 표시한다.
이미지가 없으면 기존 엄격한 로짓 비교를 사용한다. 전체 FP64 재시도는 기본으로 하지 않는다.
정밀도 우선 호환 파일이 꼭 필요할 때만 `--allow-precision-fallback` 또는 화면의 고정밀
호환 옵션을 명시한다. 실제 이미지 검증 모드에서는 FP32 후보만 검사한다.

## 합격 기준

- 원본 체크포인트와 모든 제공 이미지의 top-1 분류가 일치해야 한다.
- 모든 클래스 확률의 절대 차이는 0.001(0.1%포인트) 이하여야 한다.
- 원본 1·2등 확률 차이가 그 입력의 최대 확률 오차 두 배보다 작으면 거부한다.
- 출력 형태·유한성 및 seeded/zero/dynamic batch 요청 시 batch 2도 같은 정책으로 검사한다.
- 기존 로짓 오차 검사는 그대로 유지하되 이 정책에서는 진단 수치로 기록한다.
  이는 기존 로짓 수치 일치 기준과 동일하지 않다. `classification_dataset_v1`로 명시한다.
- 제공하지 않은 이미지나 별도 고객 프로그램의 confidence 임계값 동작까지 인증하지 않는다.

최적화/원본 FP32와 ORT 설정·스레드 후보들을 검사한다. 검증을 통과한 후보 중 실제 이미지의
관측 처리시간이 모두 8ms 이하인 후보를 우선하고, 같은 조건에서 전처리+추론+후처리 p95가
가장 작은 파일을 선택한다. 그 파일을 다시 열어 전체 검사를 반복한다.
파일 읽기/디코딩 시간은 제외한다. 모든 관측 처리시간이 8ms 이하인지는 별도 `target_met`에
기록하며 내보내기 검증 통과와 속도 목표 충족을 구분한다. 하드 실시간 보장은 아니다.

검증 중 이미지 내용이 바뀌면 해당 결과를 사용하지 않는다. 보고서에는 이미지 수와 내용
지문, 기준, 오차, 실행 설정, 처리시간을 저장하며 이미지 자체나 파일명은 저장하지 않는다.

## 회귀 검증

실제 ORT로 로짓 공통 이동(분류 확률 동일)을 허용하고 기존 엄격 검사는 거부하는 것을 구분한다.
분류 변경, 큰 확률 차이, 경계 근처 결과, NaN은 거부한다. 클래스 누락 거부, 실패 시 기존
파일 보존, 선택된 배포 파일 재로딩, FP64 자동 호출 차단, GUI 프로젝트별 경로 연결을 검사한다.
비공개 사용자 체크포인트의 실제 성공 여부는 로컬 내보내기의 보고서로 확인해야 한다.
