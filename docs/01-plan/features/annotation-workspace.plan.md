# Detection과 Segmentation 라벨링 도구 개선 계획

작성일: 2026년 10월 22일

상태: 9.23 로컬 구현·검증. Windows 설치본·실기기 승인 대기.

최종 저장 규칙과 구현 범위는 [구현 설계](../../02-design/features/annotation-workspace.design.md), 실제 검증 결과와 남은 출시 조건은 [구현 분석](../../03-analysis/annotation-workspace.analysis.md)을 따른다. [실제 실행 화면](../../02-design/assets/annotation-workspace-implemented.png)은 합성 8×16 데이터로 촬영했다.

기준 소스: `20d406f4b7e42af9f94eae90b2cefce4c96c73ab`

DeepStudio의 Windows 라벨링 화면을 공통 편집기로 정리한다. 목표는 박스와 마스크를 빠르게 만들고, 잘못 그린 부분을 쉽게 수정하고, 저장한 결과가 학습 데이터와 정확히 일치하도록 하는 것이다. CVAT의 객체 편집, Roboflow의 연속 작업과 AI 제안, Label Studio의 영역 관리, MVTec Deep Learning Tool의 데이터 준비 흐름을 참고한다.

기본 조작과 저장 신뢰성을 먼저 완성한 뒤 8×16 칩 배열 도구와 로컬 AI 보조를 추가한다. 기존 모델이나 ONNX 추론 경로를 변경하는 작업은 포함하지 않는다. 아래 성능 수치는 **출시 검증 목표이며 측정 결과가 아니다.**

## 1 참고 제품에서 가져올 것

공식 문서와 공개 화면을 기준으로 비교했다. 각 제품 전체를 직접 설치해 사용한 벤치마크는 아니다. 오른쪽 열은 DeepStudio에 적용할 설계이며, 해당 제품이 그대로 제공한다고 주장하는 내용이 아니다.

|---|---|---|
| [CVAT 도구 패널][cvat-tools], [객체 패널][cvat-objects] | 도구와 객체 목록 분리, 객체 잠금·숨김, 커서 기준 확대, 여러 객체 선택 | 왼쪽 도구·중앙 이미지·오른쪽 객체 목록. 선택 상태를 화면과 목록에서 동기화 |
| [CVAT 브러시 편집][cvat-brush] | 브러시·지우개·다각형으로 마스크 추가/빼기, 도구별 크기 설정, 완료 후 다음 마스크 작업 | 지우는 범위를 명시하고 결과 픽셀을 즉시 표시. 브러시 한 획을 별도 객체로 계속 늘리지 않고 선택한 영역을 수정 |

| [Roboflow Smart Select][rf-smart] | SAM으로 마스크 미리보기, 클릭·박스 입력, 추가 수정, 확정 | 로컬 SAM2 기반 제안 → 수동 수정 → 확정. AI 결과를 바로 정답으로 저장하지 않음 |
| [Roboflow Annotate][rf-annotate] | 이미지 작업 이력, 검토·승인 흐름, 박스와 개별 영역 라벨링 | 반복 작업 중 클래스·도구 유지, 이미지별 편집 이력과 검수 상태 표시 |
| [Label Studio 라벨링 가이드][ls-label], [예측 데이터][ls-prediction] | 영역과 클래스의 분리, 영역 목록, 초안, 예측과 정답의 구분 | 클래스를 먼저 등록할 수 있도록 유지. 초안·AI 제안·확정 정답을 별도 관리 |

제품의 조작 원칙을 참고하며 로고·아이콘·소스·스크린샷을 배포 앱에 복제하지 않는다. Windows/PySide6 기반과 로컬 파일 작업을 유지한다. 라벨링을 위해 Docker, 외부 계정, 클라우드 업로드를 요구하지 않는다. 기존에 탑재된 SAM2를 우선 활용하며 새 모델 도입은 별도 검토한다.

## 3 화면 구성

[편집 화면 배치 시안 — PNG](../../02-design/assets/annotation-workspace-wireframe.png) · [확대 가능한 SVG](../../02-design/assets/annotation-workspace-wireframe.svg)

```text
┌ 프로젝트 / 태스크 / 이미지 이름 ── 임시저장 상태 ── 저장 ── 검수 완료·다음 ┐
├ 도구 ┬ 현재 도구 설정: 클래스 / 크기 / 편집 범위 / 투명도 ┬ 클래스·객체·이력 ┤
│ 선택 │                                                │ 클래스 검색      │
│ 박스 │                                                │ 클래스 추가      │
│ 다각 │                 원본 이미지                     │ 객체 목록        │
│ 브러 │             선택 윤곽 + 수정 핸들                │ 잠금 / 표시      │
│ 지움 │                                                │ 선택 속성        │
│ 채움 │                                                │ 오류·검수 항목   │
│ 격자 │                                                │                  │
│ AI   │                                                │                  │
├──────┴────────────────────────────────────────────────┴──────────────────┤
│ 이미지 썸네일 / 미작업·작업 중·검수 필요·완료 필터 / 이전·다음             │
└ 좌표 · 실제 배율 · 화면 맞춤 · 선택 수 · 조작 안내                         ┘
```

- **공통 창:** Detection과 Segmentation은 같은 배치·선택·이력·저장 컨트롤을 사용한다. 태스크에 유효한 도구만 노출한다.
- **도구 패널:** 아이콘과 짧은 한글 이름, 툴팁에 단축키. 활성 도구 한 개와 지우기 대상이 항상 보인다.
- **속성 패널:** 박스에는 좌표·크기, 브러시에는 지름·대상 범위처럼 현재 작업에 필요한 설정만 표시한다.
- **객체 목록:** 안정적인 객체 번호, 프로젝트 클래스명, 잠금·숨김·미검수 표시. 드래그 정렬이 클래스 번호를 바꾸지 않는다.
- **색:** 앱의 중립 배경을 사용한다. 표 전체 배경을 클래스색으로 칠하지 않는다. 색상은 작은 클래스 표식과 이미지 윤곽에 사용하며 상태는 글자·아이콘을 병기한다.
- **창 크기:** 1366×768과 1920×1080, Windows 100/125/150/200% 배율에서 확인한다. 가용 논리 폭이 1100px 미만이면 보조 패널을 접고 한 번에 하나씩 연다. 필수 저장·취소 버튼은 항상 접근 가능해야 한다.
- **원본 확인:** 1:1 보기, 커서 기준 확대, ROI 확대, 화면 맞춤, 잠깐 오버레이 숨기기를 제공한다. 밝기·대비 조절은 화면에만 적용하고 학습 이미지·마스크는 바꾸지 않는다.

## 4 편집 동작 명세

### 공통 조작

| 입력 | 동작 |
|---|---|
| `V` | 선택 도구. 클릭 선택, Shift+클릭 추가 선택, 빈 곳 드래그로 여러 객체 선택 |
| `R` | 사각형. 완성 후 도구·클래스를 유지하여 연속 생성 |
| `P` / `B` / `E` | 다각형 / 브러시 / 지우개. Detection에서 E는 객체 클릭 삭제로 명확히 표시 |
| `F` / `G` | Segmentation 채우기 / 격자 후보 생성. 해당 태스크에서 지원하는 도구에만 적용 |
| Space 누르는 동안 또는 마우스 가운데 버튼 | 화면 이동. 놓으면 이전 도구로 복귀 |
| 휠 / `0` / `Ctrl+1` | 커서 기준 확대 / 화면 맞춤 / 원본 1:1 |
| `Ctrl+Z` | 그리는 중에는 최근 점·진행 중 획 취소, 그 외에는 마지막 완료 작업 취소 |
| `Ctrl+Y` 또는 `Ctrl+Shift+Z` | 다시 실행 |
| `Esc` | 진행 중 작업 취소. 다시 누르면 선택 해제. 편집창은 닫지 않음 |
| `Enter` | 다각형 또는 AI 제안 확정. 이미지 검수 완료와 구분 |
| `Delete` / `Ctrl+D` | 선택 객체 삭제 / 복제. 여러 객체는 한 번에 처리하고 한 번에 실행 취소 |
| 방향키 / Shift+방향키 | 선택 객체를 원본 1px / 10px 이동. 텍스트 입력 중에는 적용하지 않음 |
| `Ctrl+S` / `J`·`K` / `Ctrl+Enter` | 정답 저장 후 유지 / 초안 보존 후 이전·다음 / 검수 완료 후 다음 |
| `1`~`9` | 표시된 클래스 단축키. Segmentation은 전경 클래스를 우선 배정하고 배경·무시 영역은 명시적 선택 |

한글 입력·검색·숫자 입력 중에는 캔버스 단축키가 동작하지 않아야 한다. 현재 도구의 조작 예고를 하단에 표시하고 변경 가능한 단축키 표를 제공한다. `J/K`와 같은 기존 탐색 키는 유지하되 저장 상태의 의미 변경을 첫 사용 안내에 표시한다.

### Detection

1. 드래그 중 박스와 원본 픽셀 크기를 표시한다. 작은 클릭 실수는 박스로 저장하지 않는다.
2. 선택 박스의 8개 핸들로 크기를 바꾸고 내부 드래그로 이동한다. 핸들 크기는 화면 배율과 무관하게 일정하다.
3. 겹친 박스는 같은 지점 반복 선택 또는 우클릭 후보 목록으로 바꿔 선택한다. 숨긴 객체는 화면 선택에서 제외하고 잠긴 객체는 이동·삭제하지 않는다.
4. 여러 박스의 클래스·이동·복제·삭제를 한 작업으로 처리한다. 잠긴 객체가 포함되면 적용 대상 개수를 미리 표시한다.
5. 회전 핸들은 회전 박스를 지원하는 OBB 계약에서만 제공한다. 일반 Detection에 회전 박스를 저장해 학습 결과를 바꾸지 않는다.

### Segmentation

1. **다각형:** 클릭으로 점 추가, 첫 점 근처에서 닫힘 예고, Enter로 완료. 완료 후 변 클릭으로 점 추가, 꼭짓점 삭제·이동. 교차·퇴화 영역은 위치와 함께 알리고 확정을 막는다.
2. **브러시:** 원본 픽셀 단위 지름을 표시하고 원형·사각형을 지원한다. 선택한 영역에 더하기가 기본이며, 새 영역 생성은 별도 동작이다. 빠른 드래그 사이를 보간해 끊긴 획을 막는다.
3. **지우개:** 기본은 선택한 영역, 선택이 없으면 활성 클래스다. 별도 설정으로 전체 편집 가능 영역을 지울 수 있으며 잠금은 보호한다. 전체 영역 옵션은 이미지 이동 시 기본으로 복귀한다.
4. **지우기 결과:** 대상 픽셀을 배경 0으로 만들고 그 자리에 원본 이미지가 보여야 한다. 흰색 획·새 전경 객체를 추가하지 않는다. 겹친 아래 도형이 다시 나타나지 않도록 최종 합성 결과에 지우기 규칙을 적용한다.
5. **채우기:** 같은 클래스의 연결 영역 또는 닫힌 경계 내부를 미리 보여주고 확정한다. 배경 전체로 번지는 상황은 적용 면적을 표시한다. 허용오차를 쓰는 영상 기반 자동 채우기는 후속 고급 기능이다.
6. **영역 선택:** 다각형·브러시 결과·기존 PNG의 유효 픽셀을 클릭해 선택한다. 메타데이터가 없는 PNG는 클래스 영역으로 편집하고, 객체 분리가 필요하면 연결 성분 분리를 미리보기 후 적용한다.
7. **겹침:** 기본적으로 잠기지 않은 영역을 덮어쓸 수 있되, `배경에만 그리기` 옵션을 제공한다. 잠금·숨김은 서로 다르다. 숨김은 표시만 변경하며 학습 마스크는 그대로다.
8. **무시 영역:** 값 255는 별도 `학습 제외 영역` 도구로 표시한다. 배경 지우기와 혼합하지 않는다. 구멍이 있는 마스크를 폴리곤으로 바꿀 때 구멍을 조용히 채우지 않는다.

브러시 선택과 영역 편집은 화면 동작만으로 해결할 수 없다. 현재의 획 목록에 객체 ID·편집 대상·마스크 픽셀 선택 정보를 추가하고 저장 계약까지 함께 검증해야 한다.

## 5 칩 128개 반복 작업

격자 복제는 사용자 데이터에 맞춘 신규 기능이며 참고 제품의 동일 기능을 확인했다는 뜻이 아니다.

1. 대표 칩의 박스를 그린다.
2. 8열·16행, 첫 칩과 마지막 칩의 위치 또는 가로·세로 간격을 입력한다.
3. 이미지 위에 128개 후보와 `행/열` 번호를 미리 표시한다. 가장자리 잘림·중복·범위 초과를 알려준다.
4. 클래스와 적용 범위를 사용자가 정하고 확정한다. 생성·취소는 전체를 한 작업으로 처리한다.
5. 기울어진 배열은 3개 기준점으로 아핀 정렬하고, 원근 변형은 4개 기준점으로 보정한다. 일반 Detection은 축 정렬 박스라는 저장 제약을 유지한다.
6. 위치가 다른 칩만 수정하고, 여러 칩을 골라 클래스 변경한다. `R06 C06` 같은 행·열은 편집 속성으로 보관한다.
7. 다음 이미지에 적용할 때는 기준점을 다시 맞추고 후보로 불러온다. 자동으로 검수 완료 처리하지 않는다.

빈 칸·누락 칩에도 정상 칩 박스를 무조건 만드는 것은 금지한다. 실제 칩 검출용 박스와 슬롯별 상태 분류용 ROI는 다른 데이터다. 작업 목적에 맞는 클래스·학습 계약을 먼저 선택하고, 이상이 있는 칸을 미리보기에서 제외·수정할 수 있게 한다. 이 기능은 라벨링 시간을 줄이는 기능이며 **CPU 전체 검사 20ms를 보장하는 기능이 아니다.**

## 6 클래스와 저장 상태

클래스는 그림을 그리기 전에도 프로젝트에서 추가·이름 변경할 수 있어야 한다. 화면 정렬과 실제 학습 클래스 ID를 분리한다. 이미 저장한 라벨이 있는 클래스의 삭제·합치기는 영향 이미지 수와 ID 매핑을 확인한 뒤 전체 트랜잭션으로 수행한다.

### 이미지 상태

| 상태 | 의미 | 학습에 사용할 값 |
|---|---|---|
| 미작업 | 사용자가 아직 확인하지 않은 이미지 | 새 정답 없음. 빈 정답으로 자동 변환하지 않음 |
| 작업 중 | 저장되지 않았거나 복구용 초안이 있는 상태 | 초안 제외. 이전 확정 정답이 있다면 해당 버전을 유지 |
| 검수 필요 | 정답 파일은 저장됐지만 이번 수정의 확인이 남음 | 마지막 확정 버전 유지. 첫 작업이면 검수 전 신규 학습 반영 안 함 |
| 완료 | 라벨·클래스·영역 검사를 통과하고 사용자가 확인 | 확정한 정답 버전 |

정상 이미지에는 `객체 없음 확인` 또는 `배경만 있음 확인`을 별도로 제공한다. 기존 TXT/PNG 데이터는 가져오기 전후 학습 표본 수가 바뀌지 않게 기존 유효 라벨을 확정 기준선으로 등록하고, 검수 이력이 없다는 출처만 표시한다.

### 저장과 복구

- 드래그가 끝난 뒤 유휴 1초를 기준으로 초안을 예약 저장한다. 실제 지연시간은 측정 후 조정한다. 진행 중 다각형도 복구 정보에 포함한다.
- `Ctrl+S`는 현재 정답과 편집 정보를 저장하고 창을 유지한다. `검수 완료·다음`은 검증·저장·확정을 마친 뒤 이동한다.
- `저장 중`, `초안 저장됨`, `정답 저장됨`, `검수 완료`, `저장 실패`를 구분한다. 쓰기에 실패했을 때 완료 표시나 다음 이미지 이동을 하지 않는다.
- 이미지 ID·문서 revision을 저장 작업에 포함한다. 이전 이미지의 비동기 저장 결과가 새 이미지의 저장 표시를 바꾸지 못하게 한다.
- 임시 파일 작성과 원자적 교체를 사용한다. 여러 파일이 바뀌는 작업은 복구 저널과 일관된 revision으로 묶는다. 중간 종료·디스크 부족·권한 오류에서 이전 확정 데이터가 남아야 한다.
- 학습 시작 시 확정 라벨의 스냅샷을 고정한다. 사용자가 라벨을 고치는 동안 학습 데이터가 중간 상태를 읽지 않도록 한다.

## 7 내부 구조와 기존 데이터 호환

화면 전용 상태와 학습 데이터를 분리하되, 최종 정답의 기준은 하나만 둔다.

```text
공통 편집창
  도구 상태 / 선택 / 탐색 / 저장 상태
              ↓ 편집 명령
AnnotationDocument
  이미지 크기·ID / 클래스 매핑 / 객체 ID / revision / 명령 이력
        ├ Detection 어댑터 → 기존 정규화 좌표 TXT
        ├ Segmentation 어댑터 → 원본 크기 클래스 ID PNG
        └ 복구 초안 / 검수 상태 / 편집 메타데이터
              ↓ 확정 스냅샷
기존 태스크별 학습 로더
```

| 코드 단위 | 변경 방향 |
|---|---|
| `gui/widgets/detection_canvas.py`, `segmentation_canvas.py` | 공통 카메라 변환·선택·포인터 처리를 분리. 태스크별 그리기 도구는 구성 요소로 연결 |
| `segmentation_annotation.py`, `obb_annotation.py` | 공통 편집창·클래스 패널·객체 패널·이력 패널 사용. OBB의 기존 좌표·저장 동작 보존 |
| `annotation_navigation.py` | 초안 보존, 미완성 작업, 확정 후 이동을 명시적 상태로 처리 |
| `gui/core/mask_annotations.py` | 객체 ID, 마스크 영역 선택, 변경 타일, 이전 형식 읽기와 픽셀 동일성 검증 |
| `gui/core/dataset_editor.py` | 원자 저장·실패 복구·revision 검사·학습용 확정 경로 연결 |
| 신규 공통 모듈 | `annotation_document`, `annotation_commands`, `annotation_drafts`, `annotation_grid`, `annotation_assist` 역할로 나눔. 파일명은 상세 구현 시 확정 |
| `web/src/teaching-editor.tsx` 및 API | 새 데이터에 대한 명시적 버전 처리. 구버전 클라이언트가 새 편집 정보를 덮어쓰지 않도록 보호 |

- 내부 좌표는 원본 이미지 픽셀 기준으로 계산하고 화면 배율·DPI·패닝과 분리한다. Detection의 W/H 정규화와 기존 마스크의 W−1/H−1 좌표 규칙은 입출력 어댑터에서 명시적으로 처리한다.
- Semantic Segmentation의 픽셀당 클래스 한 개 계약을 유지한다. 편집용 영역 ID를 도입했다고 Instance Segmentation 학습이 지원되는 것은 아니다.
- v1 PNG 메타데이터와 획 순서의 합성 결과를 보존한다. 기존 벡터·브러시·지우기 문서는 호환 렌더러로 읽고 새 문서로 변환하기 전에 픽셀 동일성을 비교한다.
- 메타데이터가 없거나 외부에서 수정된 PNG는 실제 픽셀을 우선한다. 잃어버린 객체 경계를 복원했다고 표시하지 않는다.
- 정상적인 기존 파일을 열기만 해서는 변환·재저장하지 않는다. 새 편집 형식 저장 시 원본 백업과 버전 표시를 유지한다.
- 불일치가 발생하면 변환을 중단하고 기존 정답을 유지한다. 변환 전후 픽셀 차이와 클래스 매핑을 진단 자료에 남긴다.

## 8 반응성과 AI 보조

### 대용량 이미지 편집

- 원본 이미지는 축소 미리보기와 확대 타일을 사용한다. 마스크 계산은 원본 해상도를 유지한다.
- 브러시·지우개는 변경 타일만 갱신한다. Undo에는 변경 전후 타일이나 도형 차이만 저장한다.
- 객체 목록 전체 위젯을 매번 재생성하지 않는다. 객체 ID 기준 부분 갱신과 공간 인덱스를 적용한다.
- 이력은 작업 수와 메모리 예산을 함께 관리한다. 초안 저장 실패와 메모리 부족을 숨기지 않는다.
- GPU 추론·이미지 디코딩·정답 인코딩은 UI 스레드를 막지 않게 한다. 포인터 상태와 저장·AI 작업은 문서 revision으로 연결한다.

### 로컬 AI 제안

Roboflow의 마스크 미리보기와 Label Studio의 예측/정답 분리를 참고한 DeepStudio 설계다. [Smart Select][rf-smart], [예측 데이터][ls-prediction]

1. 현재 탑재된 SAM2에 점·박스 입력을 보내 후보를 만든다. 한 이미지의 임베딩은 재사용하되 이미지가 바뀌면 재계산한다.
2. 포함점·제외점을 추가하고 수동 브러시로 고친다. 후보에는 `AI 제안` 표시를 붙인다.
3. 사용자가 확정하면 한 개의 편집 명령으로 반영한다. 취소·실행 취소가 가능해야 한다.
4. 요청에는 이미지 ID·revision·요청 번호를 포함한다. 이미지 이동이나 수동 수정 후 도착한 이전 결과는 적용하지 않는다.
5. 모델 준비·추론·취소·실패 상태를 표시한다. AI가 실패해도 수동 도구와 저장 기능은 사용할 수 있어야 한다.
6. 먼저 명시적 클릭·박스 요청을 구현한다. 마우스를 움직일 때마다 자동 추론하는 기능은 실제 지연시간과 취소 처리를 검증한 후 도입한다.

## 9 개발 순서와 완료 조건

| 단계 | 구현 묶음 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| M0 기준 확정 | 재현용 이미지·기존 정답·성능 기준선, 공통 조작 명세, 화면 시안 | 두 태스크의 저장·재열기 기준 데이터와 실제 Windows 측정 환경 확보 |
| M1 편집 신뢰성 | 지우개 표시·대상, 브러시 영역 선택, 작업 상태와 Undo, 저장 후 창 유지, 호환 어댑터 | 다각형/브러시/PNG의 수정 → 취소 → 저장 → 재열기 결과 일치 |
| M2 공통 작업실 | 공통 배치, 클래스·객체 패널, 다중 선택, 점 편집, 잠금·숨김, 좌표·확대 통일 | 공통 단축키와 선택 규칙, 작은 창·고DPI, 겹침·경계 시나리오 통과 |
| M3 반복 작업과 복구 | 8×16 격자, 초안·복구·검수 상태, 타일 갱신, 학습 스냅샷 | 128개 후보 생성·부분 수정·전체 Undo, 강제 종료 복구, 성능 목표 통과 |
| M4 로컬 AI와 출시 | SAM2 제안, 취소·오래된 응답 차단, 기존 태스크 로더 통합, 패키징 | AI 결과를 수정·확정·학습에 사용하는 전체 흐름, Windows 설치본 검증 |

각 단계는 전후 조작 화면, 테스트 결과, 남은 제한을 함께 기록한다. M1만 끝났을 때 전체 편집기가 완성됐다고 표시하지 않는다. 작업을 나눠 병합하더라도 M0~M4 완료표를 한 문서에서 관리한다.

앱 버전은 실제 기능 출시 시 사용자 규칙인 버그 수정 +0.01, 간단한 기능 +0.1, 신규 기능 +1.0에 맞춰 결정한다. 이 계획서와 시안 작성으로 앱 버전을 올리지 않는다.

| A09 | 저장 실패·디스크 부족·강제 종료·재시작 | 이전 확정 정답 보존, 초안 복구, 잘못된 저장 완료 표시 없음 |
| A10 | 8×16 격자 생성·일부 제외·다중 클래스 수정 | 128개 후보를 정확히 생성. 하나의 Undo로 생성 전체 취소 |
| A11 | AI 작업 중 이미지 이동·수동 수정·취소 | 오래된 결과가 다른 이미지나 새 revision에 반영되지 않음 |
| A12 | 미작업·정상 확인·검수 필요 이미지로 학습 시작 | 미작업을 정상 라벨로 만들지 않음. 학습 표본 수와 확정 라벨 일치 |
| A13 | 기존 Detection TXT·v1 PNG·외부 수정 PNG 가져오기 | 원본 보존, 합성 결과 동일, 지원하지 않는 형식은 명확히 알림 |
| A14 | 설정·표 숨김·밝기 조절 후 저장 | 표시 설정이 클래스·좌표·마스크 픽셀을 바꾸지 않음 |
| A15 | Windows 설치본에서 오프라인 편집·저장·학습 로딩 | 별도 설치 없이 기본 수동 도구 작동. 탑재 AI 자산 경로도 확인 |

기존 `tests/test_detection_annotation.py`, `test_segmentation_annotation.py`, `test_mask_annotations.py`를 유지하고 실패 복구·공통 명령·PNG 왕복 테스트를 확장한다. Qt 이벤트 테스트만으로 마무리하지 않고 실제 Windows 화면에서 마우스·키보드 조작을 확인한다. Detection과 Segmentation 각각 저장 산출물로 해당 태스크의 데이터 로더를 실행한다.

### 성능과 사용성 목표

기준 데이터는 합성 8열×16행 칩 이미지, 4096×4096 이미지, 128개 객체, 1,000개 객체 스트레스 사례, 구멍·경계·희소 클래스가 있는 마스크다. 사용자 비공개 이미지의 외부 업로드는 필요하지 않다.

| 항목 | 목표와 측정 방법 |
|---|---|
| 입력 → 화면 반영 | 4096×4096 / 128개 객체에서 브러시·이동의 p95 33ms 이하, 100ms 초과 정지 없음. Windows CPU·배율·브러시 크기를 기록 |
| 이미지 탐색 | 인접 이미지 디코딩 캐시가 준비된 경우 p95 200ms 이하. 처음 읽기 시간은 별도 기록 |
| 메모리 | 50개 이미지를 왕복한 뒤 이미지·문서 캐시가 설정 예산으로 회수되고 계속 증가하지 않음. undo·타일·AI 메모리를 분리 측정 |
| 반복 작업 | 같은 작업자·같은 이미지로 이전/개선 버전을 번갈아 사용. 128개 박스 배치와 예외 수정의 중앙 작업시간 50% 이상 감소 목표 |
| 수정 품질 | 기준 정답 대비 잘못된 클래스·누락 영역·경계 오류가 증가하지 않음. 속도 개선만으로 합격 처리하지 않음 |
| 추론 회귀 | 편집기를 닫은 상태에서 기존 추론 세션·출력·스레드 설정이 바뀌지 않음. AI 보조 실행 시 자원 사용은 별도로 측정 |

CPU 종류를 모르는 상태에서 수치를 보장하지 않는다. 최초 Windows 기준 측정 후 목표를 조정한다면 이유·전후 수치를 기록한다. 라벨링 반응성 목표와 칩 전체 추론 20ms 목표는 별도로 관리한다.

## 11 첫 구현 묶음

첫 작업은 **지우개 표시·대상 수정, 브러시 영역 선택, 저장 후 창 유지, 그리기 중 실행 취소, 기존 PNG 보존 검증**으로 묶는다. 이후 공통 화면과 다중 편집을 연결한다. 이 순서로 사용자가 매일 겪는 오류를 먼저 없애고, 격자·AI 기능이 같은 편집·저장 기반을 사용하게 한다.

새 편집기를 기존 편집기와 선택 가능한 내부 기능 플래그로 검증한 뒤 기본값으로 전환한다. 되돌릴 때 구버전이 새 형식을 덮어쓰지 않도록 차단하고, 원본 백업 또는 호환 내보내기 산출물을 사용한다.
