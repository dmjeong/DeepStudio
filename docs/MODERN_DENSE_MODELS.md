# 최신 분할·이상 탐지 모델 (15.88)

새 모델은 기본 제공 목록에서 선택한다. Docker 팩은 필요 없다.

| 태스크 / 선택 이름 | 사전학습 범위 | 기본 입력 | FP32 / INT8 |
|---|---|---:|---|
| Segmentation / EfficientViT B0 + Detail | ImageNet 백본 | 448 | 둘 다 지원 |
| Segmentation / EfficientViT B1 + Detail | ImageNet 백본 | 448 | 둘 다 지원 |
| Segmentation / SCTNet Small + Detail | 공식 ImageNet 백본 | 448 | 둘 다 지원 |
| Segmentation / EoMT DINOv2-S + Detail | DINOv2-S 백본 | 448 | 둘 다 지원 |
| Anomaly detection / Dinomaly DINOv2-S/14 | 고정 DINOv2-S 인코더 | 224 | 둘 다 지원 |

모두 RGB/BW8, 중앙 크롭, 패치 학습, 수평 반전·회전·색상 변화 설정, 원본 비교를 지원한다.
`Detail`은 원본 해상도의 세부 특징 경로를 추가한 Studio 변형이다.
공식 논문의 완성된 검사 가중치나 논문 성능을 제공한다는 뜻은 아니다.

## 준비와 학습

`gui/build.bat`은 기본 가중치를 준비한다. Python 실행자는 `gui/update_segmentation_models.bat`으로
가중치를 갱신할 수 있다. DINOv2-S 파일은 EoMT와 Dinomaly가 공유한다. 실행 중 임의 다운로드는 하지 않는다.
SCTNet의 공식 Google Drive 파일에 접근할 수 없는 환경에서는 가중치 관리 화면의 수동 가져오기를 사용한다.
파일 이름뿐 아니라 고정 SHA256과 백본 텐서 구조를 검사한다.

분할 프로젝트에서 기존처럼 클래스별 영역을 그리고 학습 화면에서 새 모델과 `사전학습 가중치로 시작`을 고른다.
배경은 0, 제외 영역은 255이다. 분할 헤드는 내 정답으로 학습한다.
작은 크랙을 유지하려면 **패치 학습 / 패치 배율 100%**로 시작한다. 입력 크기는 패치 한 변이다.
반전·회전이 실제 불량을 정상으로 바꾸는 공정이면 해당 증강은 0으로 설정한다.
학습 결과의 클래스별 지표, best epoch, 에폭 시간과 CSV를 확인한다. 로컬 가중치 전이·중단 재개도 지원한다.

새 모델들은 전역 문맥/어텐션을 사용하므로 패치 학습 후 **같은 크기의 겹치는 타일**로 추론한다.
큰 ROI 전체를 새로운 입력 크기로 강제 변경하지 않는다. 앱과 ONNX JSON/C++가 같은 배율·크롭·타일을 사용한다.
100% 배율은 원본을 축소하지 않는다는 뜻이다. 모델 내부의 특징 축소나 검출 성능까지 보장하는 뜻은 아니다.

## 교사 증류

학습 화면의 **분할 교사 증류**에서 더 좋은 기존 Studio 분할 체크포인트를 선택한다.
교사와 학생의 클래스 이름·순서, 입력 채널, 정규화가 같아야 한다. 교사는 학생과 **동일한 증강 패치**를 보고,
255 영역을 제외한 픽셀의 확률 분포를 학습에 사용한다. 교사 파일 해시·혼합 비중·온도를 기록한다.
재개 시 다른 교사나 다른 증류 설정을 섞으면 오류를 낸다.
배포에는 학생만 포함된다. 교사 추론은 학습 중에만 추가되며 학생 추론에는 교사가 필요 없다.
SAM2 프롬프트 모델이나 Docker 모델 팩의 증류는 이 경로에서 지원하지 않는다.

## Dinomaly

`train/good`(또는 `normal`)의 정상 영상, `val/good`, 선택적인 `val/불량명`을 준비한다.
정상 검증 영상이 없으면 정상 학습 영상 일부를 결정론적으로 분리한다. Test는 학습·임계값 보정에 쓰지 않는다.
최소 2장이 필요하지만 충분한 품질을 보장하는 개수는 아니다.

인코더는 고정하고 재구성기를 여러 에폭 학습한다. Best는 **정상 검증 재구성 손실(val_loss)**로 선택한다.
학습 후 정상 검증 점수의 최대값보다 높은 임계값을 저장한다. 검증 정상에서의 오검출 0은 미래 데이터 보장이 아니다.
UI 점수는 판독용 정규화 값이고 C++의 `score/threshold`는 같은 판정을 내는 **원시 코사인 거리 점수**다.
PatchCore의 코어셋 비율은 적용되지 않는다. 무작위 고정 인코더로 시작하는 모드와 AMP는 제공하지 않는다.

## ONNX·INT8·암호화

내보내기에서 정밀도 `FP32` 또는 `INT8 QDQ`를 고른다.
INT8은 출력 검증을 켜고 **실제 보정 영상 폴더**를 지정한다. 기본값은 Train 폴더이며 마스크 폴더를 지정하지 않는다.
먼저 원본 PyTorch와 FP32 ONNX를 비교한 뒤 INT8로 변환하고 실제 영상을 동일 전처리로 실행해 비교한다.

- FP32: 원본 체크포인트 대비 수치 검증.
- INT8: 실행·유한 출력·보정 영상의 FP32 대비 픽셀 일치율/클래스 IoU 또는 이상 점수·판정 차이 기록.
- `verification=int8_compared`는 정확도 불변이나 독립 시험 통과를 뜻하지 않는다. 별도 Test로 확인한다.
- 암호화는 두 정밀도 모두 지원한다. 같은 ONNX를 암호화한 전후의 출력은 동일하다.
- INT8이 항상 빠르지는 않다. 대상 Windows CPU의 Release/x64에서 구간별 시간을 비교한다.

고정 타일 배포는 JSON **schema 8**이다. 예전 SDK는 지원 버전 오류를 낼 수 있다.
ONNX와 JSON을 같이 교체하고 `cpp/include`, `cpp/src` 전체로 런타임을 다시 빌드한다.
새 파일 `dense_tiles.h`를 빠뜨리지 않는다. JSON의 타일 크기를 임의로 바꾸지 않는다.

[인자 없는 C++ 예제](../example/cpp/dense_models/README.ko.md)는 초기화·워밍업 후 `Segment(image)` 또는 `Anomaly(image)`를 호출한다.
FP32/INT8 호출 코드는 같다. 암호화 파일은 `InitializeFromPackage`로 연다.
C#은 기존 `sdk/csharp`의 native runtime 래퍼와 이번 버전으로 빌드한 `vision_runtime.dll`을 함께 사용한다.

## 검증 범위

합성 데이터와 실제 사전학습 백본으로 학습·저장·복원·FP32/INT8·C++·암호화·화면 연결을 검사한다.
사용자 데이터의 검출력, 3500×1500 Windows/i7 지연시간, Windows 설치 EXE 실행은 별도 실측 대상이다.
SegMAN의 CUDA selective-scan/NATTEN 경로는 CPU 기본 모델에 포함하지 않았다.
출처와 구현 차이는 [라이선스 기록](../licenses/modern-dense-models.md), 실행 결과는 [검증 보고서](03-analysis/modern-dense-models.md)를 참고한다.
