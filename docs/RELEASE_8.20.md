# 8.20 — 암호화 내보내기 버그 재검증

버그 수정 규칙에 따라 8.19에서 8.20으로 올렸다. 암호화 기능의 정상 경로뿐 아니라
원본 파일 보존, 외부 가중치, Windows 경로, 잘못된 패키지와 반복 초기화를 재검토했다.

- 암호화 출력과 원본 외부 가중치가 겹치면 거부한다.
- 진단 보고서가 체크포인트나 키를 덮어쓰거나 삭제하지 않도록 보호한다.
- sparse initializer/Constant, 중첩 그래프, 함수의 외부 tensor를 모두 내부에 포함한다.
- Windows에서 `graphs/model.onnx` 같은 패키지 이름을 OS 경로로 바꾸지 않는다.
- Python/C++가 중복 필드와 잘못된 그래프 계약을 동일하게 거부한다.
- SDK 선택 변경 시 CMake의 이전 ONNX 헤더/라이브러리 캐시를 폐기하고,
  배치 빌드 폴더를 소스 위치·SDK·빌드 환경에 따라 구분한다.
- C#에서도 전 태스크의 평문/암호화 결과 일치, 키 삭제 후 추론, 반복 해제 및 오류 복구를 검사한다.
- `with_opencv` 폴더로 빌드할 때 `encrypted.cpp`를 찾지 못하는 오류를 수정한다.
- 웹 내보내기의 암호화 선택·키 경로·출력을 프로젝트별로 유지한다.

추론의 연산·전처리·정밀도·최적화 설정은 바꾸지 않았다. 초기화의 입력 검사와
내보내기만 수정했다. Windows/v141/BCrypt와 실제 eVision/i7 실행은 로컬에서 검증하지
못했으며 CI 검사를 추가했다. 상세: [재검토 보고서](ENCRYPTION_AUDIT_2026-09-29.md).
