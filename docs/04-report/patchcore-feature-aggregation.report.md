# PatchCore 특징 집계 수정 결과 — 11.71

사용자 조건은 **이미 잘라 놓은 224×224 고정 격자**다. 이전 전체 트레이 축소 실험만으로 사용자 원인을 설명할 수 없다.

## 반영한 수정

1. 신규 정상 뱅크는 layer2/3 각각의 원래 격자에서 3×3 평균을 낸 뒤 확대·결합한다. 이전에는 확대 후 평균을 냈다. 공개 Anomalib 집계 순서와 대조했다.
2. 특징 집계를 체크포인트 schema 6에 명시한다. schema 1~5 및 추가 학습은 기존 계산을 유지한다. 기존 모델에서 새 뱅크를 구축할 때만 새 집계와 현재 점수 방식으로 전환한다.
3. 검증 F1 기준의 판정을 유지하면서 인접 검증 점수 사이에 기준을 놓는다. 검증 경계 샘플에서 실제 발견한 PyTorch/ORT 판정 뒤집힘을 방지했다. 새로운 영상이 기준에 근접하는 경우까지 보장하지 않는다.

## 품질 근거와 남은 문제

합성 RGB 트레이 고정 격자, 공식 ImageNet ResNet18, 정상 원본 4장(448패치), 코어셋 1,024개, seed 0. val 2장·정상 보정 2장만으로 기준을 설정했다. 이전 진단에서 사용했던 시험 10장을 재사용한 탐색 실험이다.

같은 중간값 보정 정책으로 비교: 기존 15/33 불량 패치 검출·정상 9/1,087 오검출, 수정 23/33·0/1,087. layer1/2로 바꾸는 후보는 15/33·3/1,087로 개선되지 않아 제외했다. 패치에 결함 픽셀이 조금이라도 포함되면 양성으로 분류했으며, 칩/결함 개수 기준 검출률과는 다르다.

**수정 후에도 불량 패치 10개를 놓쳤다.** 사용자의 원시 점수 분포·비공개 영상은 확인하지 못했으며 이 구현 차이가 사용자 문제의 유일한 원인이라고 주장하지 않는다. 화면의 0~1 변환은 단조 증가하므로 점수 차이를 압축하지만 그 자체가 정상·불량 순서를 뒤집지는 않는다.

## 검증

- PatchCore 학습·증강·저장·이전 체크포인트·UI·ONNX·실제 C++ 회귀 등 **136개 통과**. 로그 `/tmp/dvs-patchcore-11.71-final.log`.
- 집계 구현을 독립적인 3×3 패치 전개/평균과 대조. 기존·신규 집계가 서로 다름과 각 경로가 정의된 계산을 수행함을 확인.
- 기존/신규 집계 × 기존/신규 점수 × 크롭/전체 × 학습/새 입력의 C++ 회귀 16개 포함.
- 공식 사전학습 제품 모델의 336패치 원시 점수가 연구 구현과 정확히 일치.
- 저장·복원·ONNX 이후 실제 C++까지 14패치 점수·지도·판정 확인. PyTorch/ORT 점수 최대 오차 `1.79e-6`, 지도 `6.38e-6`, ORT/C++ 점수 `4.94e-9`. 새 기준에서 판정 일치.
- Ruff E/F/W 검사 및 `git diff --check` 통과.
- macOS/Apple M4만 실행. Windows·원격 CI·사용자 생산 영상은 미검증. 푸시하지 않았다.

최초 제품 배포 시험은 검증 경계 샘플의 판정 불일치로 실패했다. 이를 숨기거나 오차 허용치를 늘리지 않고 검증 점수 사이 보정을 구현해 재검증했다. 기존 F1 점수 경계에서는 이전 집계가 12/33·FP8, 새 집계가 23/33·FP0이었다. 중간값 보정은 검증 판정을 유지하지만 새로운 시험 입력에는 영향을 줄 수 있어, 최종 표에는 양쪽 모두 같은 보정 정책을 적용한 수치를 사용한다.
