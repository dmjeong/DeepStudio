# PatchCore 증강 및 코어셋 진행 정보 검증 — 11.70

## 원인과 변경

- PatchCore는 UI capabilities와 위젯 활성화에서 증강을 차단했고 `PatchCoreDataset`에도 증강이 없었다. 원본당 추가 view 수(기본 0)와 좌우 반전·반사 테두리 회전·색상 변화를 연결했다. 원본 view는 이전과 동일하며 평가·추론에는 적용하지 않는다.
- 코어셋 요청 수는 전체 특징 수 × 비율이지만 후보/메모리 잔여 용량으로 제한된다. 이전에는 이 차이와 단계별 시간이 드러나지 않았다. 요청/실제 수, 제한 사유, 실제 비율, 특징 추출/선별 시간을 로그·체크포인트·CSV에 기록했다.
- 기존 프로젝트의 동작은 증강 수 0으로 보존한다. 추론 코드, 특징 차원, 점수 계산, 임계값 정책은 변경하지 않았다.

## 검증

- 관련 Python/Qt/C++ 통합 회귀 **116개 통과**, 종료 코드 0. 증강·시드·원본 보존·검증 미적용·UI 값 편집/복원·프로젝트 이동 저장·추가학습 용량 제한·학습 CSV·실제 ONNX 산출물의 C++ 로드 포함.
- 새 증강 테스트에서 전역 Python/NumPy/Torch RNG를 변경하지 않고 같은 이미지/view/시드가 동일한 결과를 생성함을 확인했다. 원본과 기본 평가 데이터의 전처리는 정확히 일치한다.
- 실제 ImageNet ResNet18로 원본 8장 + 추가 증강 16장 = 24장을 앱 워커에서 처리했다. 전체 18,816패치 중 10% 요청 1,881개, 후보 4,096개, 뱅크 한도 128개이므로 실제 저장은 128개(0.68%)였다. 로그에 제한 원인을 확인했다.
- 실제 실행 로그의 특징 추출 0.236초, 코어셋 선별 0.005초는 macOS 4스레드의 작은 합성 데이터 동작 확인 값이다. 목표 Windows 장비의 처리량이나 검출 성능을 뜻하지 않는다.
- 증강 학습 체크포인트 저장/재로드/ONNX 검증 성공. 별도 합성 시험 12장의 PyTorch↔ONNX 점수 최대 절대 차이 `2.4e-6`, 지도 `1.3e-5`, 판정 모두 일치.
- Qt offscreen에서 실제 증강 폼을 렌더링해 추가 장수·설명·세 설정이 잘리지 않는 것을 확인했다. CI 범위 정적 검사와 `git diff --check` 통과.

## 사용과 한계

학습 → 고급 설정 → 데이터 증강 → 원본당 추가 증강 수를 1 이상으로 설정하고 변형을 선택한다. 반전/회전이 검사할 불량이면 해당 항목은 0으로 두어야 한다. 적용하려면 정상 특징 뱅크 재구축과 판정 기준 재보정이 필요하다.

증강 개수와 비율이 클수록 정확도가 높아진다고 보장하지 않는다. 후보 전체를 선택하는 경우 코어셋 선별을 생략할 수 있으므로 시간도 비율에 단순 비례하지 않는다. 정상 데이터만으로 판정 임계값을 정하는 별도 정책, 고해상도 PatchCore 타일 추론, 대상 Windows/EXE 실행은 이번 검증 범위 밖이다.
