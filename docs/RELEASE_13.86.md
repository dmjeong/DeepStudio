# 13.86 — 원본 비교와 복수 앱 CPU 추론

## 수정

원본 비교: Grad-CAM 없이 결과 이미지를 그릴 때 오른쪽 결과만 갱신되어 왼쪽에 이전 이미지가
남는 경로를 재현하고 수정했다. 프로젝트를 비울 때도 이전 원본을 지운다. 비교 버튼을 켤 때
현재 이미지 경로를 확인하며, 추론 당시 저장한 원본을 먼저 사용한다. 동일한 파일명이 서로
다른 폴더에 있어도 경로로 구분한다. 추론 후 같은 경로의 사진이 교체돼도 결과와 원본이 짝을 유지한다.

복수 실행: 데스크톱 창 자체에는 중복 실행 금지가 없었지만 모든 앱의 계산이 같은
`compute.lock`을 사용했다. CPU 모델 확인/추론을 별도 작업 잠금으로 바꿔 다른 앱의 학습 중에도
실행할 수 있게 했다. 두 번째 작업 관리자가 첫 앱의 살아 있는 작업을 중단으로 바꾸던 문제도
PID와 시작 시각 확인으로 수정했다. 모델 메모리와 결과 디렉터리는 작업마다 독립적이다.

프로젝트 저장: 읽기만 한 창의 저장으로 학습 스냅샷이 변경되지 않도록 동일 내용은 다시 쓰지 않는다.
다른 앱이 파일을 변경했다면 이전 창의 저장은 거절하고 다시 열도록 안내한다. 새 학습 기록이
오래된 프로젝트로 덮이는 것을 막는다. 작업 중 기록 삭제/압축도 다른 앱까지 확인한다.

## 사용

- Python 데스크톱은 별도 명령 창에서 각각 `python gui/main.py`로 실행한다.
- EXE는 같은 `DeepVisionStudio.exe`를 다시 실행한다.
- 첫 앱에서 GPU 학습, 두 번째 앱의 **추론 장치에서 CPU 선택 → 모델 로드 → 추론 시작**.
- 두 앱 모두 CPU 추론도 가능하다. 각 앱 안에서는 계산 작업 한 개씩이며 GPU/변경 작업의 기존
  공유 잠금은 유지된다. CPU/RAM을 함께 사용하므로 단독 실행과 같은 속도를 보장하지는 않는다.
- 같은 프로젝트를 여러 창에서 수정한 경우 저장 충돌 안내에 따라 최신 프로젝트를 다시 연다.
- 이 변경은 Python/EXE 데스크톱 기준이다. 웹 서버의 포트/단일 서버 잠금은 유지한다.

기존 가중치·학습 결과·ONNX·C++ 코드를 바꿀 필요 없고 재학습도 필요 없다.
Python 실행은 소스 업데이트 후 재시작, EXE는 새 빌드를 사용한다.
