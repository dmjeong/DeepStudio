# 탐지·LibreYOLO 분류 패치 학습과 증강 (12.84)

## 적용 모델과 시작 방법

탐지는 LibreYOLO9 Tiny, Re-DETRv4 Small/Medium/Large, 새 D-FINE Nano에 적용한다.
분류는 LibreYOLO MobileNetV4 Small과 새 Medium에 적용한다.

1. 프로젝트에서 모델을 선택한다. 처음 학습할 때는 사전학습 가중치로 시작하는 모드를 권장한다.
2. **학습 → 하이퍼파라미터 → 패치 학습**을 체크한다. 입력 크기가 패치 크기다.
   현재 native 모델의 검증된 입력은 탐지 640×640, 분류 224×224로 고정한다.
3. **패치 배율**은 우선 100%로 둔다. 작은 결함을 보존하려면 축소 배율부터 낮추지 않는다.
4. **데이터 증강**에서 좌우 반전 확률, 회전 각도, 색상 변화를 수정한다. 0은 해당 증강을 끈다.
   반전/회전 자체가 불량인 과제라면 그 증강을 사용하지 않는다.
5. 학습 로그의 적용 증강과 패치 설명을 확인한다. 실제 적용 값은 체크포인트와 best CSV에 남는다.

GUI와 웹 화면 모두 설정을 저장한다. 중단 재개에서는 저장된 입력 영역·패치·증강을 유지한다.
설정을 바꾸려면 기존 가중치를 이용한 **추가 학습**을 선택한다.
기존 일반 이미지 모델은 계속 사용할 수 있지만, 새 패치 판정 방식을 사용하려면 패치 옵션으로 학습해야 한다.

## 패치의 의미

**탐지:** 원본의 train/val/test 구분을 유지한 채 25% 겹치는 격자로 자른다.
박스도 함께 자르고, 물체가 없는 배경 패치도 학습한다. 원본 파일은 수정하지 않는다.
이미지당 패치 수 0은 모든 패치, 양수는 고정된 seed로 뽑은 학습 패치 수다.
양수 제한은 작은 결함이 있는 패치를 제외할 수 있으므로 처음에는 0을 권장한다.
검증에는 항상 모든 패치를 사용한다. **학습 대시보드의 검증 mAP는 패치 단위**이며,
원본 전체에서 박스를 합친 뒤 평가한 점수와 다르다. train과 val 원본 영상이 각각 필요하다.

**분류:** 원본 한 장의 라벨을 유지한다. 모든 패치를 모델에 넣고 클래스별 최대 logit을
모아 원본 한 장을 판정하는 MIL 방식이다. 불량 이미지에서 잘라낸 모든 정상 조각에
불량 라벨을 강제로 붙이지 않는다. 원본은 한 장씩 학습하고, 배치 크기는 한 번에 모델에
넣는 패치 수다. 원본 전체의 역전파 그래프는 유지되므로 패치가 많으면 GPU 메모리가 증가한다.
Grad-CAM은 최종 예측 클래스의 최대 logit을 만든 패치에 표시하며 나머지 영역을 억지로 색칠하지 않는다.

패치보다 작은 영상은 우측·하단을 회색(114)으로 채운다. 명시적으로 지정한 중앙 ROI는 패치 분할 전에 적용한다.
추론도 저장된 배율·겹침·합치기를 사용한다. 탐지 결과는 원본 좌표로 복원하고 클래스별 NMS로 중복 박스를 제거한다.
**패치는 추론 횟수를 늘린다. 전체 축소 방식보다 빠르다는 보장은 없다.**

## 증강 수정의 실제 적용

종전 native 탐지 경로는 UI 값을 전달하지 않고 엔진의 별도 증강을 사용했다.
이번에는 세 개의 UI 값으로 이미지와 박스를 함께 변환한다. 숨은 mosaic, mixup, 임의 crop,
추가 scale jitter는 끈다. 분류에도 동일한 UI 설정을 전달한다.
학습에서만 증강하고 검증·추론에서는 적용하지 않는다. 검증의 이중 리사이즈도 제거해
학습·앱·ONNX/C++와 같은 색상 순서·스케일·리사이즈를 사용한다.

## 추가 모델과 가중치

| 선택 | 용도와 비교 기준 | 배포 가중치 |
|---|---|---|
| D-FINE Nano (COCO) | 작은 박스의 위치 추정을 비교할 추가 탐지 후보. 현재 모델보다 빠르거나 정확하다고 단정하지 않는다. | LibreDFINEn.pt, COCO-only |
| LibreYOLO MobileNetV4 Medium | Small의 표현력이 부족할 때 비교할 분류 후보. 더 큰 모델이므로 속도·메모리도 함께 비교한다. | LibreMobileNetV4m-cls.pt |

두 배포 가중치의 게시 라이선스는 Apache-2.0이다. D-FINE의 Objects365 파생 가중치는 추가하지 않았다.
[모델 카드·출처·고지·SHA-256](../licenses/native-models-12.84.md)을 함께 기록했다.

Python 사용자: 앱과 같은 Python 환경을 활성화한 상태에서 **gui/update_native_models.bat**을 실행한다.
처음 출력되는 Python 경로를 확인한다. 전체 EXE를 다시 빌드할 필요 없이 런타임과 새 모델 두 개를 준비한다.
새 설치/EXE 빌드에서는 기존 build.bat의 기본 가중치 준비 과정에 포함된다.

## ONNX, 암호화, C++/C#

내보낸 ONNX 한 번의 실행은 패치 한 개를 처리한다. 전체 영상 자르기와 결과 합치기는
JSON의 **schema 7 / patches** 계약을 읽는 최신 SDK가 실행한다.
일반 ONNX와 암호화 패키지 모두 지원하며, 원본 한 장의 판정/좌표를 반환한다.

- [명령행 인자 없는 C++ 예제](../example/cpp/native_patches/README.md): exe 옆 모델을 한 번 초기화하고 준비 추론 후 재사용.
- C#은 최신 `vision_runtime` 라이브러리로 재빌드한다. 기존 C ABI를 통해 동일한 패치 처리 경로를 사용한다.
- 구형 `with_evision/classifier.h` 단독 로더는 schema 7을 지원하지 않는다. JSON의 patches를 지우거나
  버전 숫자를 낮추면 학습 때와 다른 판정이 되므로 최신 공통 SDK를 사용한다.

D-FINE/Re-DETR의 query 순번은 객체 ID가 아니다. ONNX 검증은 박스 집합을 대응시켜 비교하며,
동점 때문에 달라지는 낮은 점수 query는 최종 검출 기준 0.25 이상에서 재검증한다.
이 범위는 JSON에 기록되고 SDK는 그보다 낮은 임계값이나 검증 범위를 넘는 검출 개수를 거부한다.
seeded/zero 입력 검증은 사용자 생산 영상의 검출률 검증을 대체하지 않는다.

## 확인한 범위

- 실제 LibreYOLO 1.5.0: YOLO9 Tiny, Re-DETRv4 Small, D-FINE Nano, MobileNetV4 Small/Medium의
  합성 데이터 1 epoch 학습 → best 저장/복원 → ONNX → C++ 실행.
- 추가 두 모델은 공식 사전학습 가중치를 내려받고 원본 백본 가중치가 로드된 것을 확인한 뒤,
  클래스 2개로 미세조정하고 내보내기까지 실행.
- 박스 자르기·배경 보존·증강·검증 전처리·분류 MIL/Grad-CAM·암호화 출력 일치 검사 16개 통과.
- 기존 기능을 포함한 Python/Qt 회귀 검사 312개 통과, 2개 건너뜀.
  이후 추가한 검증 전처리 3개와 Runtime/내보내기를 포함한 57개를 재실행해 프로세스 종료 코드 0까지 확인했다.
- macOS ARM64 C++17 Release 빌드 및 CTest 7개 통과. 웹 빌드 및 테스트 14개 통과.
- Windows SDK CI에도 실제 native 패치 학습/내보내기 검사를 연결했다.
  **로컬 Windows/i7·CUDA GPU·사용자 생산 이미지의 정확도와 속도는 측정하지 않았다.**

실행 중 발견한 macOS ONNX Runtime 종료 크래시는 진단 정보 전송 스레드의 mutex에서 발생했다.
이 앱의 CPU 세션·native exporter·공통 C++ SDK에서 Runtime telemetry를 끄고 관련 검사를 재실행했다.
추론 최적화·스레드 수·출력 계산에는 영향을 주지 않는 초기화 설정이다.
