# 5.87 — EfficientNet ONNX 수치 검증 재발 수정

## 신고와 확인 범위

저장소 `bugfix`에 보고된 최적화 그래프 최대 오차는 0.0065917224, 원본 그래프는
0.0050078034, 실행 설정 재시도는 0.0021469593이다. 진단 그래프의 최초 차이는
`features.4`다. 이 정보만으로 특정 BatchNorm 또는 CPU 커널이 원인이라고 확정할 수는 없다.
사용자 체크포인트와 Windows PC에서의 재현은 수행하지 않았다.

## 반복 원인과 코드 수정

기존 재시도는 Conv/BN 융합, 상수 폴딩, ORT 최적화 설정을 바꿨다. 원본 ONNX의
BatchNormalization 연산 자체가 PyTorch와 다른 반올림으로 계수를 계산하는 경로는
그대로 남았다. 기본 초기화 모델 위주의 테스트는 학습된 정규화 통계의 오차 증폭을
충분히 다루지 못했다. 또한 융합 후보를 그 후보의 PyTorch 출력과 비교하여 원본 모델과
변환된 모델 사이의 차이를 놓칠 수 있었다.

이번 수정은 기존 재시도가 실패했을 때 PyTorch 평가 커널에서 scale/offset을 구해
ONNX Mul/Add로 저장하는 추가 후보를 검증한다. Conv에 계수를 합치지 않고 ORT 최적화를
끄며, 모든 후보를 동일한 원본 체크포인트에 비교한다. CPU autocast도 내보내기와
검증에서 비활성화한다. 기존 atol=0.001, rtol=0.0005와 top-1 검사는 그대로다.
seeded, zero 및 dynamic batch 요청 시 batch 2를 모두 통과해야 배포하며,
실패하면 기존 ONNX/JSON 파일을 보존한다. 앱의 자동 ONNX 추론에도 같은 변환을 적용했다.

## 검증

- macOS ARM64, Python 3.14, PyTorch 2.14.0, ONNX Runtime 1.29.0에서 실제 실행.
- running mean=1000, variance=0.001인 3채널 BatchNorm에서 최적화를 끈 기존 ONNX와
  PyTorch의 최대 차이 0.00390625를 관측. PyTorch 계수 고정 그래프의 차이는 0이었다.
  이는 같은 종류의 수치 문제 재현이며 사용자 체크포인트의 직접 재현은 아니다.
- 공개 ImageNet EfficientNet B0 가중치의 기본 그래프 및 추가 변환 경로 비교 수행.
- 회귀 테스트: 학습 통계 BN 실행, 원본 출력 기준 변조 검출, 새 재시도의 모든 probe 검증,
  배포 JSON 재로딩 및 앱 추론 재시도. 관련 93개 테스트 통과(앱 테스트의 안내 문구 회귀 수정 후 재실행 포함).
- `onnx-parity.yml`은 Windows/Linux에서 설치파일 빌드나 기본 가중치 다운로드 없이
  해당 수치 회귀 검사를 독립 실행한다. 로컬 결과는 Windows 결과를 대신하지 않는다.

이 수정이 모든 체크포인트의 수치 일치를 보장하거나 CPU 8ms 성능을 보장하지는 않는다.
기존 체크포인트로 내보내기를 다시 실행할 수 있으며, 이 오류만으로 재학습을 요구하지 않는다.
