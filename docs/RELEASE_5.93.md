# 5.93 — EfficientNet ONNX 분류 판정 기반 FP32 검증

## 원인
새 `bugfix` 로그의 3채널 EfficientNet은 모든 엄격 FP32 로짓 비교를 실패했다.
가장 가까운 후보는 ONNX Runtime 최적화 끔·CPU 4스레드에서 최대 로짓 오차가
0.078231812였지만, PyTorch와 ONNX의 top-1 클래스는 같고 1·2등 로짓 간격은
약 78.8이었다. 기존 코드는 실제 이미지 검증 폴더가 있을 때만 분류 판정 기준을
사용했고, 그 외에는 로짓 절대 오차만으로 내보내기를 거부했다.

## 구현
엄격 검증에 실패한 EfficientNet 분류 모델은 FP64 전에 FP32 후보를 다시 평가한다.
검정·회색·흰색, 수평·수직 그라데이션, 체크무늬, 고정 seed 난수 4종, 기존 seeded와
zero 입력을 사용한다. 동적 배치 모델은 서로 다른 두 입력을 묶은 batch 2도 검사한다.

각 입력에서 다음 조건을 모두 만족해야 한다.

- PyTorch와 ONNX의 top-1 클래스가 같다.
- softmax 확률의 최대 차이가 0.001 이하이다.
- PyTorch 판정 마진이 확률 오차의 2배보다 크다.
- PyTorch와 ONNX의 1·2등 확률이 동률이 아니며 최소 마진을 넘는다.
- 출력에 NaN 또는 무한대가 없다.

융합 FP32, 원본 FP32, BatchNorm 계수 고정 두 방식과 ONNX Runtime 최적화·스레드
설정을 비교한다. 통과 후보는 모델 추론 중앙값을 측정하고 가장 빠른 파일을 다시
열어 전체 입력을 재검증한 뒤 저장한다. 선택 정책, 입력 수, 확률·로짓 오차, 최소
마진, 실행 설정과 측정 시간은 배포 JSON에 기록한다.

## 검증 범위
프로젝트에서 클래스별 실제 이미지 폴더를 찾으면 기존 `classification_dataset_v1`
검증을 우선하며 모든 실제 이미지를 검사한다. 실제 이미지가 없을 때 사용하는 새
`classification_synthetic_probe_v1`은 결정론적 합성 입력에 대한 인증이다. 완료 화면과
JSON에서 이 범위를 명확히 구분한다. 합성 검증 실패 후에만 사용자가 허용한 FP64
경로를 시도한다.

사용자 체크포인트는 보안상 전달받지 않았으므로 로컬에서 직접 실행하지 않았다.
대신 로짓 전체에 0.02 차이를 주어 엄격 검증은 실패하지만 분류 결과가 보존되는 실제
ONNX를 생성해 새 정책의 계산, 후보 선택, 최종 재로딩과 manifest 기록을 검사한다.
