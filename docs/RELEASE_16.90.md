# 16.90 — 이미지 이름 변경 복구와 모델 실행 패키지 누락 수정

## `No module named timm`

새 모델의 의존성은 requirements에 있었지만 기존 Python 환경에서 소스만 업데이트하면 설치되지 않았다. 기존 segmentation 업데이트 배치는 `--no-deps`로 timm만 설치해서 timm의 하위 의존성이 빠진 환경도 복구하지 못했다.

Python으로 실행 중이라면:

1. 앱을 종료하고 최신 소스를 받는다.
2. **`gui/repair_model_runtime.bat`을 실행한다.** 모델 실행 패키지만 설치한다. EXE 빌드와 가중치 다운로드는 하지 않는다.
3. 완료 후 앱을 다시 실행한다. 기존 학습 데이터/가중치는 그대로 사용한다.

Python을 여러 개 설치한 PC에서는 앱 오류에 표시된 실행 Python을 배치의 인자로 전달한다. 또는 오류에 표시된 `"실제 python.exe 경로" "repair_model_runtime.py 경로"` 명령을 실행한다. `--check`는 설치 없이 import만 검사한다.

복구는 현재 Python의 `-m pip`를 사용하며 기존 torch/torchvision/numpy의 버전(예: `+cu128` 포함)을 constraints로 고정한다. timm·SciPy와 필요한 하위 패키지를 설치한 뒤 새 프로세스에서 실제 import를 검사한다. 실패를 성공으로 표시하지 않는다. EXE는 이 스크립트로 고칠 수 없으며 새 배포판이 필요하다. EXE 빌드 사전 검사에도 timm/SciPy/safetensors를 추가했다.

공통 생성 경로에서 U-Net MobileNetV4·EfficientNet-B1, EfficientViT B0/B1, EoMT 의존성을 먼저 검사하므로 학습·저장 모델 로드·export에서 같은 복구 안내를 제공한다. SCTNet은 DropPath 하나 때문에 필요했던 timm 의존성을 제거했다. 체크포인트 키와 추론 연산은 그대로다.

## 탐색기에서 이미지 이름을 바꿨을 때

`images/train/A.png`와 `masks/train/A.png`는 상대 경로와 이름으로 연결한다. 이미지만 `B.png`로 바꾸면 정답은 옛 이름으로 남는다. **프로젝트 저장은 설정 저장이며, 어느 정답을 어느 이미지에 붙일지 추측할 수 없다.**

- 데이터셋 화면 상단의 **정답 연결 복구** → 이전 마스크 선택 → 새 이미지 선택 → 겹쳐 보이는 영역 확인 → **이 정답 연결**.
- 이후 이름 변경은 이미지 우클릭 → **이름 변경 (정답 함께)**. 이미지와 마스크/박스/폴리곤 파일을 함께 변경한다.
- 프로젝트 저장 후 외부 변경을 다시 스캔한다. 연결이 끊긴 정답의 수와 복구 버튼을 표시한다.

같은 분할에서 사용자가 고른 연결만 적용한다. 기존 정답 덮어쓰기, 크기/클래스 범위 불일치, 이름 충돌은 거부한다. 원본은 `.deep_studio_dataset_archive`에 보관하며 저장 실패 시 복원한다. 대응 관계가 확인되지 않은 이미지를 정상 배경으로 학습시키거나 오래된 마스크를 무시하지 않는다.
