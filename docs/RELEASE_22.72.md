# 22.72 — EfficientNet 내보내기 검증 입력과 오류 진단 수정

## 확인한 문제

`bugfix`의 3채널 100×100 모델은 일부 검사에서 PyTorch와 ONNX의 판정이
각각 1번·3번으로 달랐습니다. 작은 숫자 오차만 있는 경우가 아닙니다.
모델 버전 시각을 기록하기 전의 검증 단계이며, 버전 기능과 관계없습니다.

코드에는 별도의 검증 입력 결함이 있었습니다. 정규화한 공간에 무제한 난수를
직접 생성해서 영상에서 나올 수 없는 값까지 넣고 있었습니다.
ImageNet 정규화·seed 42·1×3×100×100을 재현하면 30,000개 값 중 979개가
원래 픽셀 범위 0~255 밖으로 환산됩니다. 이 검사가 먼저 실패하면 나머지 입력은
검사하지 못합니다. 이것이 해당 비공개 모델의 모든 출력 차이를 일으켰다는 뜻은 아닙니다.

## 수정

- 먼저 0~255의 픽셀을 만든 뒤 체크포인트의 정규화를 적용합니다. 최초 엄격 검증,
  합성 입력 대체 검증, 실제 이미지 추가 검증의 난수 입력에 동일하게 적용합니다.
- 검정·회색·흰색·그라데이션 등의 추가 입력도 유효 범위를 확인합니다.
  합성 분류 판정 정책은 `classification_synthetic_probe_v2`로 기록합니다.
- 기존 합격 조건인 판정 일치, 확률 오차, 판정 경계 검사를 유지합니다.
  실제 이미지 비교를 선택하면 제공된 모든 이미지도 통과해야 합니다.
- 오류창은 대표 실패·실패 입력·수치 진단을 표시합니다. 여러 `norm affine` 후보를
  포함한 전체 실패 내용은 `.export-error.json`에 보존합니다.
- PyTorch의 FP32·FP64 비교에서 숫자만 다른 경우와 클래스까지 달라지는 경우를 구분합니다.
  합성 대체 경로의 실패도 그래프·실행 설정·검사 입력별로 기록합니다.
- 추론 코드나 학습 가중치는 바꾸지 않습니다. 검증 실패 시 기존 배포 파일을 보존하며,
  느린 FP64 계산을 사용자 선택 없이 활성화하지 않습니다.

## 사용

앱을 갱신하고 재시작한 뒤 기존 `.pt`로 다시 내보내면 됩니다.
이 검증 코드 수정 때문에 재학습할 필요는 없습니다.
실제 검사 입력에서도 같은 판정인지 확인하려면 내보내기 화면의 실제 이미지 추가 검증에
로컬 검증 이미지 폴더를 지정하세요. 이미지나 가중치를 외부로 보내지 않습니다.
평면 이미지 폴더도 가능하며, 프로젝트의 이미지 0장 클래스 폴더는 필수가 아닙니다.

`norm affine`은 원본 변환이 실패했을 때 정규화 연산을 다른 형태로 표현하는 대체 후보 이름입니다.
그 후보가 실패했다는 메시지만으로 학습 모델의 BatchNorm이 고장 났다고 판단하지 않습니다.
업데이트 후에도 유효 입력에서 판정이 달라지면 배포를 중단합니다.

## 검증 범위와 한계

회귀 검사는 유효 픽셀 범위·난수 재현성, RGB 100×100 실제 ONNX 실행,
합성/실제 이미지 정책의 판정 불일치 거부, 상세 진단 보존,
기존 ONNX·JSON 보존, B0/B1 및 정밀도 대체 경로를 포함합니다.
macOS에서 관련 13개 테스트 파일의 139개 검사를 통과했습니다. FP16 내보내기,
암호화 시 기존 파일 보호, 모델 버전 보존, GUI 프로젝트 연결도 포함합니다.
수치 검증에는 테스트 모델을 사용합니다. 사용자의 비공개 체크포인트와
Windows 검사 PC에서 이번 오류가 해소됐는지는 여기서 확인할 수 없습니다.
현재 로그만으로 재학습이 필요하다고 결론내리지 않습니다.
