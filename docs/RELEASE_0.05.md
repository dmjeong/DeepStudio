# 0.05: ONNX 검증 실패 원인 진단 보강

0.04의 원본 그래프 재시도에도 EfficientNet B0 검증이 실패했다는 사용자 보고가 있다.
현재 확인된 실패 지점은 ONNX 파일 생성 이후 PyTorch와의 출력 비교다. 사용자 Windows
PC의 비공개 체크포인트에서 최대 오차 27.9941이 발생한 원인은 아직 확정하지 못했다.
이 릴리스는 해당 오류의 해결 완료나 재학습 필요성을 주장하지 않는다.

## 변경

- 두 그래프가 모두 실패하면 실제 실패한 입력과 ONNX 파일로 추가 진단한다.
- 기본 ONNX Runtime 세션과 스레드 수를 제한한 ALL/BASIC/DISABLED 세션을 비교한다.
  0.04의 원본 재시도는 변환 전 융합·폴딩·단순화를 제외했지만 ORT 실행 최적화는
  기본값이었다. 이번 비교로 변환 단계와 실행 단계의 차이를 구분한다.
- PyTorch 반복 실행, FP32/FP64 출력, 가중치·BatchNorm 통계의 유한성을 확인한다.
- 별도의 임시 그래프로 EfficientNet 9개 특징 추출 단계와 최종 출력을 비교한다.
  중간 출력 추가 자체가 그래프 최적화를 바꿀 수 있으므로, 진단 그래프의 최종 출력과
  원래 실패 파일의 출력 비교도 기록한다. 최초 허용 오차 초과 단계가 곧 원인 연산이라는
  의미는 아니다.
- 오류창의 `수치 진단:`과 로컬 `*.export-error.json`에 결과를 남긴다. 버전, 스레드,
  CPU 정밀도 설정과 집계 수치만 추가하며 이미지·가중치·중간 출력 배열은 추가하지 않는다.
  외부 전송은 없다. 기존 진단 파일의 경로·오류 문구에는 로컬 경로가 포함될 수 있다.
- 진단은 실패 시에만 실행되며 추가 시간과 메모리를 사용한다. 가중치, 검증 허용 오차,
  top-1 조건을 바꾸지 않고 실패 시 기존 배포 파일을 보존한다.
- README에 EXE 재빌드 없이 기존 Python 환경에서 소스 버전을 실행하는 방법을 추가했다.
- Windows CI에서 UTF-8 테스트가 정상적인 CRLF를 LF와 비교해 실패하던 기대값을 수정했다.
  기본 줄바꿈과 명시적 LF/CRLF를 모두 검사한다. 콘솔 동작 변경은 없다.

## 검증과 한계

macOS ARM64, Python 3.12.13, PyTorch 2.14.0, ONNX Runtime 1.29.0에서 내보내기·진단
관련 30개 테스트가 통과했다. 실제 B0 1×1×224×224 ONNX로 단계 비교, 가중치·기존 파일
보존, 임시 파일 정리를 확인했다. 별도 테스트에서 ONNX 분류기 bias를 의도적으로 바꿔
실패 파일과 새 진단 그래프의 결과가 다를 때 이를 구분하는지도 확인했다.

공식 ImageNet B0 가중치로 별도 실험했다. 224×224, seed 42 입력에서 1채널 변환과
3채널, 사전 융합 유무, ORT ALL/BASIC/DISABLED 조합은 모두 기존 수치·top-1 검사를
통과했다. 최대 절대 오차는 1채널 약 1.01e-5, 3채널 약 4.63e-6 이하였다.
이는 사용자 모델의 재현 결과나 Windows/i7 검증 결과가 아니다.

원인 확정에는 실패 PC에서 생성한 추가 진단 결과가 필요하다. 최대 오차 숫자만으로
변환 문제, 런타임 계산 차이, 학습된 모델의 수치 민감도를 구분할 수 없다.
