# 5.89 — 고정밀 ONNX 속도 저하 수정

## 실제 신고

이번 `bugfix`는 내보내기 실패가 아니라 5.88의 `portable_fp64` 검증 통과 후 속도 저하다.
B1, 1채널 100×100, 4클래스, CPU 4스레드이며 ONNX 크기는 52.2MB다.
FP32 실패에 대응하여 모든 연산을 FP64로 올렸고 모든 Conv에 unfold를 사용한 것이
계산량과 메모리 사용을 늘렸다. 실제 추론 속도가 사용자 목표를 만족하는지는 검사하지 않았다.

## 변경

1. 앱의 자동 추론은 전체 FP64를 생성·재사용하지 않는다. FP32 경로가 실패하면 검증된
   기존 PyTorch 실행으로 복귀한다. 명시적 ONNX에서 FP64를 쓰면 화면에 속도 경고를 표시한다.
2. 고정밀 1×1 Conv는 채널 MatMul로, depthwise Conv는 공간 Gather 및 FP64 합산으로
   처리하여 불필요한 unfold와 다수의 작은 MatMul을 줄인다. 입출력은 FP32다.
3. 명시적 내보내기에서 전체 FP64가 통과하면 일부 구간을 FP32로 바꾸어 원본 모델과
   비교한다. seeded/zero 및 동적 배치 요청 시 batch 2를 모두 통과해야 속도를 측정한다.
4. 워밍업 2회 후 7회 모델 실행시간 중앙값을 측정하고 기존 후보도 재측정한다.
   최소 5% 빨라진 후보만 저장한다. 동시에 다른 ORT 세션을 유지하지 않아 유휴 스레드 풀의
   간섭을 줄인다. 기록된 속도는 모델 연산만이며 전·후처리는 포함하지 않는다.
5. 처음 검증된 파일을 따로 보존한다. 느리거나 수치가 틀린 후보는 거부하고, 최종 파일을
   다시 읽어 같은 원본과 같은 스레드 설정으로 검증한다. 더 빠른 혼합 모델을 찾지 못하면
   검증된 고정밀 모델을 유지하고 그 사실을 표시한다.

최대 12개 후보를 탐색하며 후보 사이에서 30초 제한을 확인한다. 진행 중인 export를
강제로 중단하는 시간 제한은 아니다. 탐색은 내보내기 때 수행되며 추론 버튼마다 실행하지 않는다.
전체 후보 공간의 최적 속도나 특정 i7에서 8ms를 보장하지 않는다.

## 검증 범위

실제 ORT에서 일반/그룹/stride/dilation Conv, batch 1로 내보낸 모델의 batch 3 실행,
B1 100×100 혼합 정밀도와 두 grayscale 계약, 원본 상태 불변을 검사한다.
빠르지만 오답인 후보와 정확하지만 느린 후보를 모두 거부하는 테스트, 탐색 중 오류·시간 제한
시 파일 보존, 최종 재로딩 검사 및 앱 자동 실행 회귀 검사를 추가했다.
사용자 체크포인트나 목표 Windows PC의 시간은 직접 측정하지 않았다.

별도 공개 ImageNet B1 가중치(1채널 변환, 100×100, 1000클래스)를 macOS ARM64,
ORT 1.29.0, 4스레드에서 측정했다. ORT만 실행한 별도 프로세스의 21회 중앙값은
5.88 전체 FP64 37.61ms, 선택된 혼합 그래프 4.73ms였고 이전 그래프 재측정은 34.69ms였다.
이 공개 모델은 모든 feature stage를 FP32로 되돌리고 분류 head만 FP64로 유지해
seeded/zero/batch 2를 통과했다. 이는 사용자의 4클래스 체크포인트 또는 i7에서 측정한 값이 아니다.
