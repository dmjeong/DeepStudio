# 프로젝트별 생성 및 배포 설계

## 생성

Data Gen 첫 탭에 프로젝트 클래스 생성 모드를 제공한다. 클래스는 project.data.class_names에서 읽고, 생성 방식은 별도 선택한다. 선형/얼룩/결손/입자/질감/국소 변형/색상 변화 기법을 임의 클래스에 연결한다. 이름만으로 결함의 물리적 의미를 추정하지 않는다. 크기·강도·시드는 사용자가 지정한다.

학습 분할 원본만 읽고 기존 정답 영역을 보존한다. segmentation은 배경 위치에만 합성하고 클래스 ID 마스크를 만든다. detection/OBB는 기존 박스를 보존하고 합성 영역의 박스/회전 사각형을 추가한다. classification은 선택한 클래스 폴더를 만든다. anomaly는 합성 평가 전용 결과로 구분하고 정상 train에 합치지 않는다.

프로젝트 내부 generation 작업 폴더에 후보 PNG와 정답을 저장한다. 프로젝트 클래스 목록·task·원본 해시·시드·생성 기법을 manifest에 기록한다. 후보 검수 후 새 버전 디렉터리에 저장한다. 클래스 변경/후보 변조를 검사하며 동일 후보 재저장은 중복 없이 복구한다. 생성과 저장은 독립 작업 프로세스로 수행한다.

## 배포

PyInstaller 분석 경로에 python/과 프로젝트 루트를 명시하고 실제 신규 모델 임포트를 frozen 스모크에서 확인한다. 사용자에게 배포하는 DLL 배치를 그대로 C++ 한글 경로 실행 테스트에 사용한다. UI 작업 스레드 수명과 종료 처리를 점검한다.

Windows Actions에서 EXE 빌드, 모델 임포트, 창 생성, 추론, 새 생성 모드 저장, MSI 설치 및 제거를 검증한다. 테스트를 생략하거나 오류를 무시해 통과시키지 않는다.

설치 빌드는 WiX 5.0.2와 같은 버전의 확장을 사용한다. 작은 MSI는 Setup EXE에 포함한다. 원본 payload 1.5 GiB 초과는 외부 CAB·MSI·Setup을 ZIP64 하나로 묶어 단일 MSI/서명 EXE의 용량 제한을 피한다. 사용자 PC는 압축 해제 후 Setup 한 번으로 설치하며 설치 중 패키지나 가중치를 내려받지 않는다. 작은 실제 Setup 두 방식의 설치·제거를 먼저 검사하고, 통과해야 큰 GUI 설치본을 빌드한다.
