# 13.86 — 원본 비교와 복수 앱의 CPU 추론

## 계획

사용자가 고른 이미지의 원본·결과가 항상 한 쌍으로 표시되어야 한다.
두 번째 앱에서 CPU 추론할 때 첫 앱의 GPU 학습 때문에 막히거나 작업 기록이 중단으로 바뀌면 안 된다.

## 설계

- 비교 화면 원본을 현재 이미지 경로에 연결하고 비교 버튼을 켤 때도 경로를 확인한다.
  Grad-CAM 유무와 무관하게 원본을 갱신하고, 파일/캐시가 없으면 이전 원본을 지운다.
  추론 시 저장한 원본을 우선하므로 이후 같은 경로의 파일이 바뀌어도 결과와 짝이 맞는다.
- CPU infer/inspect_model은 읽기 전용 계산으로 다른 앱의 학습 잠금과 분리한다.
  같은 작업 관리자는 여전히 한 작업씩 수행한다. GPU 계산·학습·변경 작업의 기존 잠금은 유지한다.
- 새 앱의 작업 관리자 초기화에서 살아 있는 다른 앱/워커를 중단 상태로 바꾸지 않는다.
  PID와 프로세스 시작 시각을 함께 확인하고, 작업 기록도 디스크의 최신 상태를 읽는다.
  진행 중인 다른 앱 작업의 삭제/압축을 차단한다.
- 프로젝트를 여러 앱에서 열었을 때 오래된 화면의 저장으로 최신 학습 기록이 덮이지 않게 한다.
- 복수 실행은 독립 모델 메모리를 사용한다. CPU 추론 중에도 CPU 자원·메모리는 필요하므로
  두 앱 속도의 무조건적인 보장은 하지 않는다.

## 검사

서로 다른 원본·같은 파일명의 폴더·Grad-CAM on/off·선택/정렬/캐시 복원·누락 파일을 검사한다.
두 관리자를 동시에 열고 CPU 작업이 compute.lock과 공존하는지, GPU 경로는 보호되는지,
실행 중 기록·취소·삭제·재시작 복구와 프로젝트 저장 충돌을 검사한다.
가능한 경로는 실제 자식 프로세스와 Qt 이벤트 루프에서 실행한다.
