대상은 `deepstudio3`의 `bb294762a8feefbe7d0ec8d79d092e5d9b0df480`이다. 이 기록에서는 모델 코드나 앱 버전을 변경하지 않았다. 실행 시각, Python 버전, 개별 검사 결과, 대상 파일의 SHA-256은 [24.8-results.json](24.8-results.json)에 기록했다.

## 실제 실행 결과

`tests.test_efficientnet_channels`와 `tests.test_efficientnet_deployment`의 18개 검사를 실행했다. 10개가 통과했고 8개는 필요한 라이브러리가 없어 건너뛰었다. 검증 래퍼는 건너뛴 검사가 있으면 종료 코드 2와 `blocked`를 반환했다. unittest의 `OK (skipped=8)`은 모델 실행 성공으로 해석하면 안 된다.

가중치 합산의 별도 NumPy 계산은 고정 난수의 float64 가중치와 홀수, 짝수, 1x1 입력에서 실행했다. stride 2와 0 padding을 사용했으며 최대 절대 오차는 `5.329070518200751e-15`였다. 동일하게 정규화한 흑백 3면에 대한 첫 Conv와 합산 가중치의 1면 Conv를 비교한 결과다. 사전학습 가중치, 구형 채널별 RGB 정규화, 전체 네트워크 출력, 정확도, 속도를 검증한 수치가 아니다.

## 코드에서 확인한 범위

- 새 1채널 모델은 native 경로에서 첫 Conv 입력을 1채널로 구성한다. forward의 RGB 정규화 확장은 구형 어댑터 경로에만 존재한다.
- 구형 1채널 체크포인트는 첫 Conv 3채널 구조를 유지한다. 기존 파일을 다시 ONNX로 내보내는 것만으로 새 1채널 stem이 되지 않는다.
- 새 stem의 공식 RGB 가중치는 채널 방향 합산으로 초기화한다. 기존 구형 모델과의 예측 동일성이나 정확도 유지를 보장하지 않는다.
- 입력 버퍼 재사용은 24.8에 구현되지 않았다.

위 항목은 소스 검사 결과다. 실행 중 실제 입력 텐서를 관찰한 결과와 구분해야 한다.

## 실행 차단 근거

현재 Python 3.12 환경에 torch, torchvision, cv2, onnx, onnxruntime이 없다. PyPI의 OpenCV 인덱스와 공식 PyTorch CPU 인덱스 요청 모두 HTTP 403과 `Forbidden. Calls to this URL via the terminal are not allowed.` 응답을 받았다. uv를 통한 공식 CPU 인덱스 설치도 완료되지 않았다.

[대상 커밋의 CI 실행](https://github.com/dmjeong/Vision/actions/runs/35197019288)은 실패했으며 검사 작업은 실행된 step이 없고 runner ID가 0이다. 실패 원인의 상세 annotation은 커넥터에서 읽을 수 없었다. 결제, 권한 또는 코드 오류라고 추정하지 않는다. 이 CI 결과도 모델 테스트 통과 증거가 아니다.

## 남은 검증

실제 라이브러리를 갖춘 실행 환경에서 위 8개 검사를 건너뜀 없이 완료하고 `tools/efficientnet_pretrained_smoke.py`로 실제 공식 사전학습 가중치를 비교해야 한다. 정확도, 혼동행렬, 추론 시간은 실제 학습 및 평가 실행이 추가로 필요하다. C++ 빌드와 전체 학습 UI 동작도 이 기록에서는 검증하지 못했다.

관련 검사 실행 명령은 다음과 같다. unittest의 성공 종료만 보지 말고 `skipped=0` 여부를 함께 확인해야 한다.

```sh
python -m unittest tests.test_efficientnet_channels tests.test_efficientnet_deployment -v
python tools/efficientnet_pretrained_smoke.py --output efficientnet-validation.json
```
